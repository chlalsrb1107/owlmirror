# 차량 장착 후 LiDAR·카메라 캘리브레이션 절차 (현장용)

> 작성: 2026-10-15 — 업체 시공으로 루프랙 구성물(카메라 4대 + VLP-16)이 차량에 고정된 직후.
> **이 절차를 끝내기 전까지 화면의 거리 숫자는 믿을 수 없다.** 코드는 준비돼 있고, 빠진 것은
> 현장 실측값뿐이다 — LiDAR 둘(`mount_height_m`, `mount_offset_deg`)과 카메라 둘
> (`hfov_deg`, `yaw_trim_deg`).
> 측정 결과는 `08_Video_Demo/config/lidar_mount.json` · `camera_mount.json`에 저장되고
> `live_demo.py`가 그대로 읽는다.
>
> 최종 파이프라인이 **소리 → 카메라 지목 → 그 대상의 LiDAR 거리 → 화면**이므로, 네 값 중
> 하나만 틀려도 "엉뚱한 물체까지의 거리를 그럴듯하게" 보여주게 된다.

## 왜 이 값들인가

| 값 | 틀리면 생기는 일 |
|---|---|
| `mount_height_m` (노면→라이다 원점) | 지면 제거 기준선이 어긋난다. **크게** 잡으면 노면이 물체로 남아 어느 방향을 조회하든 `h/tan15° ≈ 6~8m`가 나오고(2026-09-01에 실제로 겪은 "모든 방향 6.34m" 증상), **작게** 잡으면 차량 하단이 잘려 멀리 있는 대상을 놓친다 |
| `mount_offset_deg` (라이다 0° → 차량 전방) | 거리는 맞지만 **방향이 통째로 틀어진다.** 왼쪽에서 난 소리에 오른쪽 물체의 거리를 붙이게 되고, 화면의 점 클러스터가 실제 점군과 어긋난다 |
| `hfov_deg` (카메라 수평화각) | **박스→방위 환산이 통째로 틀어진다.** YOLO가 화면 가장자리에서 잡은 구급차의 방위가 실제와 어긋나, 그 방위로 조회한 LiDAR가 **옆 차선 차량의 거리**를 돌려준다 |
| `yaw_trim_deg` (카메라 장착 미세 오차) | 같은 문제가 작은 규모로. 2°면 30 m에서 1.05 m 어긋난다 |

마이크(ReSpeaker) 오프셋은 **별개의 값**이다 — 센서 위치가 다르다. 라이다를 먼저 맞춘 뒤
라이다를 기준으로 역산한다(6단계).

---

## 준비물

- 줄자(5m 이상), 라바콘 또는 사람 1명(표적), 분필/테이프
- 평평한 포장면, 차 주변 반경 **최소 15m가 빈 곳** (주차장 가장자리·공터)
- 노트북 + 라이다 이더넷(192.168.1.100 대역) 연결, 가능하면 차량 시동 ON(전원 안정)

> ⚠️ 측정 중에는 차를 움직이지 않는다. 시공 상태가 바뀌면(루프랙을 풀었다 조이면) 전부 다시 잰다.

## 0. 패킷이 오는지부터 확인

```bash
cd 08_Video_Demo/code
python3 lidar_calibrate.py --sectors
```

- 아무 스캔도 못 받으면: `sudo tcpdump -i <iface> udp port 2368`으로 패킷 자체를 확인.
  포트 2368, 1206바이트 패킷이 보여야 한다. 안 보이면 전원·이더넷·IP 대역 문제다.
- 30° 구역표에서 **비워둔 방향이 `—`로, 벽·건물 쪽이 실제 거리로** 나오는지 본다.
  90° 단위로 통째로 틀어져 보이면 그것만으로도 오프셋이 크다는 뜻이다.

## 1. 장착 높이

```bash
python3 lidar_calibrate.py --height
```

- 노면 리턴에서 역산한 높이가 나온다. **줄자로 잰 값(노면 → 라이다 원점, 센서 몸통 가운데)과
  5cm 안에서 맞는지** 반드시 대조한다.
- 안 맞으면: 바닥이 기울었거나(경사 주차면), 차 주변 4~25m에 물체가 많아 노면 빈을 잘못 잡은 것이다.
  더 빈 곳으로 옮겨 다시 잰다.
- **줄자 값과 추정값이 다르면 줄자 값을 믿는다.** 추정은 노면이 평평하다는 가정 위에 있다.

## 2. 요(yaw) 오프셋

1. 차량 **정면 정중앙**, 보닛에서 약 10m 앞에 표적(사람 또는 콘)을 세운다.
   차의 중심선 위에 놓는 것이 중요하다 — 1m 옆으로 벗어나면 10m에서 5.7° 오차다.
2. ```bash
   python3 lidar_calibrate.py --bearing --expect 0
   ```
3. 출력에서 확인할 것
   - **스캔 간 흩어짐 ≤ 2°** (넘으면 표적이 흔들렸거나 다른 물체를 집은 것 → 다시)
   - 표적 거리가 실제로 놓은 거리와 맞는지
4. 교차 확인: 표적을 **좌측 정옆 10m**로 옮기고 `--bearing --expect 90`. 두 추정이
   1~2° 안에서 일치하면 신뢰할 수 있다. 크게 다르면 표적 위치가 틀렸거나 라이다가 기울어 있다.

> 실시간으로 확인하고 싶으면 `python3 lidar_calibrate.py --monitor`로 표적을 들고 움직이며
> 방위·거리가 따라오는지 본다.

## 2-5. 카메라 화각·방위 (⚠️ 이번 장착에서 가장 불확실한 값)

```bash
python3 camera_bearing.py --report
```

현재 `calibration.json` 기준으로 수평화각이 **약 52.7°**로 나온다. 그런데 하드웨어 문서에는
**2.8 mm 렌즈**(이 센서에서 약 103°)로 적혀 있다. **둘 다 맞을 수는 없다.**

- 52.7°가 맞다면 카메라 4대(90° 간격)가 방위를 **37°씩, 합계 149° 비워둔다** — 그 구역의
  대상은 YOLO로 지목할 수 없고 소리 방향 경로로만 처리된다(화면이 "소리 방향"이라고 밝힌다)
- 103°가 맞다면 시야가 겹쳐 공백이 없다

### 확인 방법 (표적 하나로 두 값을 같이 잡는다)

1. 차량 **정면 정중앙 10 m**에 표적(사람/콘)을 세운다. 2단계에서 쓰던 그 자리 그대로면 된다.
2. 전방 카메라 영상을 띄운다 — `python3 preflight_view.py` 또는 `live_demo.py`.
3. **중앙 확인**: 표적이 화면 가로 정중앙에 오는가?
   - 벗어났다면 그 벗어난 각도가 `yaw_trim_deg`다. 화면 가로 폭 2048 px 기준,
     중앙에서 벗어난 픽셀 `d`에 대해 `trim ≈ -atan(d / fx) [deg]`
     (fx는 `--report`가 찍어준다. 표적이 화면 **오른쪽**으로 치우쳐 보이면 trim은 **양수**)
4. **화각 확인**: 표적을 화면 **가장자리에 겨우 걸치는 위치**까지 옆으로 옮기고, 그때 차량
   중심에서 본 표적의 방위를 재거나(줄자로 삼각형을 만들어 계산) 라이다로 읽는다 —
   `python3 lidar_calibrate.py --monitor`가 방위를 실시간으로 찍어준다.
   그 방위의 2배가 수평화각이다.
5. 결과를 `08_Video_Demo/config/camera_mount.json`에 적는다.
   ```json
   { "yaw_trim_deg": { "front": 1.2, "left": 0.0, "right": 0.0, "rear": 0.0 },
     "hfov_deg":     { "front": 103.0, "left": 103.0, "right": 103.0, "rear": 103.0 } }
   ```
   적고 나서 `--report`를 다시 돌려 공백 구역이 사라졌는지(또는 여전한지) 확인한다.

> 네 대를 다 재는 것이 가장 좋지만 시간이 모자라면 **전방 한 대만 재고 나머지에 같은 화각을
> 적용**해도 된다(같은 모델·같은 렌즈). trim은 카메라마다 다를 수 있으니 따로 보는 편이 좋다.

  경고 문구가 나오므로 적용 여부를 바로 알 수 있다.

## 4. 통합 확인 (소리 없이)

```bash
python3 lidar_distance_match.py --live --theta 0 --sigma 7 --track
```

표적을 들고 전방 → 좌측 → 후방으로 걸어가며, `--theta`를 0 / 90 / 180으로 바꿔가며
거리·방위가 따라오는지 본다. 걸어서 다가가면 `접근 x.x m/s`가 양수로 나와야 한다.

## 5. 지목 → 거리 연결 확인 (최종 경로)

젯슨까지 띄우고 실제로 소리를 내며, 화면 오른쪽 영상에서 **박스 아래 거리 판**이 뜨는지 본다.
콘솔에는 매 감지마다 이렇게 찍힌다.

```
[12:34:56] class=siren score=+4.27 theta=-14.8 rms=-31.2dB (수음~표시 지연 180ms)
    -> front 카메라로 전환, level=경고 (접근 5m/s), distance=18.3, blind=False, ...
       카메라: Ambulance 방위=-15.4° (박스 폭 ±2.1°, 소리와 -0.6° 차이)
       라이다: 거리=18.3m 방위=-15.1° (카메라 기준 +0.3° 차이) 창=±3.4° 점=142 접근=+5.2m/s
```

확인할 것

- [ ] **"카메라" 기준으로 조회되는가** — 거리 판 보조 줄이 "카메라 지목 · 라이다"인지
- [ ] **라이다 방위가 카메라 방위와 1~2° 안에서 맞는가** — 꾸준히 벌어지면 `yaw_trim_deg`
      또는 `hfov_deg`가 틀렸다는 뜻이다 (2-5단계로 돌아간다)
- [ ] 아는 거리(10 m / 20 m)에 세운 차량과 화면 숫자가 ±1 m 안에서 맞는가
- [ ] 옆 차선에 다른 차를 세워두고도 **지목한 차의 거리**가 나오는가 (이 구조의 핵심)

## 6. 마이크 오프셋 역산 (젯슨 쪽 값)

라이다 보정이 끝난 뒤에만 의미가 있다.

1. 젯슨을 평소처럼 띄운다 (`python3 -u jetson_audio_sender.py --host 192.168.10.1 …`).
2. 노트북에서
   ```bash
   python3 lidar_calibrate.py --audio-offset --samples 20
   ```
3. 표적(사이렌/경적 스피커, 또는 실제 차량의 경적) 앞에서 소리를 내며 여러 방향에서 20건을 모은다.
4. 출력된 **차이 중앙값**을 젯슨 `jetson_audio_sender.py`의 `MOUNT_OFFSET_DEG`에
   **현재 값 + 차이** 로 반영한다 (또는 `--mount-offset`으로 전달).
   표준편차가 10°를 넘으면 소리를 낸 물체와 라이다가 집은 물체가 다를 수 있다 — 주변을 비우고 다시.

> 이 단계는 그동안 "각도를 아는 위치에서 재야 한다"고만 적혀 있던 작업을, 라이다를 자(尺)로
> 삼아 자동화한 것이다. 사람이 각도기로 재는 것보다 정확하고, 여러 방향에서 모으므로
> 한 지점의 오차에 끌려가지 않는다.

```bash

python3 pipeline_selftest.py          # 가짜 센서로 파이프라인 연결 확인 (약 20초)
python3 preflight_view.py             # 카메라 4대 + 라이다 동시 수신 확인

```

실차에서 처음 돌릴 때 **반드시 눈으로 대조할 것** (코드가 알아챌 수 없는 것들):

- [ ] 각 방향에서 손을 흔들어 **카메라 방향 배정**이 맞는지 (`CAMERA_SERIAL` 유도값, 미검증)
      — 여기가 틀리면 박스→방위 환산이 90°·180° 단위로 통째로 틀어진다
- [ ] 아는 거리(10m/20m)에 세운 차량의 화면 거리 오차 — ±1m 안이면 합격
- [ ] 비어 있는 방향에 점 클러스터가 뜨지 않는지 (가짜 물체)
- [ ] 다가오는 차에 `접근 x m/s`가 양수로 뜨는지, 멀어지면 음수인지
- [ ] 주행 중 노면·연석이 물체로 올라오지 않는지 → 올라오면 `min_object_height_m`를 0.35~0.4로

## 알아둘 한계 (현장에서 당황하지 않도록)

- **접근 속도는 상대 속도다.** 자차 속도(CAN/GPS)를 안 쓰므로, 달리는 중에는 정지한
  가드레일·주차 차량도 자차 속도만큼 "접근"으로 보인다. 정차 상태에서 먼저 검증할 것.
- **반경 6m는 물리적 사각지대**다. 그 안의 물체는 거리 대신 "사각지대"로만 보고한다.
- 라이다는 소리를 내는 물체를 구분하지 못한다 — 그 방향에서 **가장 그럴듯한 물체**를
  고를 뿐이다. 그래서 카메라(YOLO)가 지목한 방위로 조회하는 것이 최종 구조이고, 지목에
  실패하면 화면이 "소리 방향"이라고 밝힌다.
- **카메라가 못 보는 방위가 있을 수 있다**(2-5단계). 그 구역에서는 아무리 기다려도 거리 판에
  "카메라 지목"이 뜨지 않는다 — 고장이 아니라 화각 문제다.
