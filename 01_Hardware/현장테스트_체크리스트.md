# 현장 테스트 체크리스트 (차량 실장착 후 첫 주행 시험)

> 작성: 2026-10-15 · 대상: 업체 시공으로 루프랙에 카메라 4대 + VLP-16이 올라간 차량
> **순서가 중요하다.** 뒤 단계는 앞 단계의 값이 맞다는 전제 위에 있어서, 건너뛰면
> "거리는 나오는데 엉뚱한 물체"를 측정값인 줄 알고 기록하게 된다.
> 측정 절차의 세부·합격 기준: [`차량장착_라이다_캘리브레이션_절차.md`](차량장착_라이다_캘리브레이션_절차.md)

예상 소요: 정지 상태 캘리브레이션 **60~90분** + 주행 시험 30분. 날이 밝을 때 시작할 것
(야간이면 카메라 노출이 올라가 YOLO가 대상을 못 잡아 2-4단계가 막힌다).

## B. 현장 0단계 — 전원·배선·패킷 (10분)

평평한 포장면, 차 주변 반경 15m가 빈 곳에 주차. **시험 내내 차를 움직이지 않는다**
(움직이면 B~E를 다시).

- [ ] 라이다 회전음이 들리고, 카메라 4대 LED가 들어온다
- [ ] 랜 어댑터 2개 인식 — `ip -br addr`에 젯슨용(192.168.10.1)과 라이다용(192.168.1.100)이 뜬다
- [ ] 젯슨 핑 — `ping -c3 192.168.10.2`
- [ ] 라이다 UDP 패킷 — `sudo tcpdump -i <라이다NIC> -c 20 udp port 2368` (1206바이트)
- [ ] 카메라 4대 + 라이다 동시 수신 — `python3 preflight_view.py`

```bash
python3 lidar_calibrate.py --sectors     # 30° 구역별 최근접 물체
```

- [ ] 비워둔 방향은 `—`, 벽·건물 쪽은 실제 거리로 나온다
- [ ] 90° 단위로 통째로 틀어져 보이지 **않는다** (틀어졌으면 C-2에서 바로잡힌다)

> ⚠️ 핑은 되는데 패킷이 안 오면 → 젯슨·노트북 IP 충돌(루프백이 답한 것).
> ⚠️ 젯슨 실행이 멈춘 것처럼 보이면 → `python3 -u`를 안 붙인 것(SSH stdout 버퍼링).

## C. 라이다 장착값 실측 (20분) — 이게 틀리면 전부 틀어진다

### C-1. 장착 높이

```bash
python3 lidar_calibrate.py --height
```

- [ ] 추정값과 **줄자 실측값(노면 → 라이다 원점)이 5cm 안에서** 일치
- [ ] 불일치하면: 더 평평한 곳으로 이동해 재측정. **줄자 값을 믿는다**

### C-2. 요(yaw) 오프셋

차량 정면 **정중앙** 10m에 표적을 세운다(중심선에서 1m 벗어나면 5.7° 오차).

```bash
python3 lidar_calibrate.py --bearing --expect 0
```

- [ ] 스캔 간 흩어짐 ≤ 2°
- [ ] 표적 거리가 실제 놓은 거리와 맞음
- [ ] 교차 확인 — 표적을 좌측 정옆 10m로 옮겨 `--bearing --expect 90`, 두 추정이 1~2° 안에서 일치

### C-3. 저장

```bash
python3 lidar_calibrate.py --height --bearing --expect 0 --write
python3 lidar_calibrate.py --sectors        # 저장값 반영 확인
```

- [ ] `config/lidar_mount.json`에 기록됨
- [ ] 전/좌/후/우가 상식과 맞음

## D. 카메라 (25분) — 순서 주의: 방향 배정 → 화각·trim

### D-1. 방향 배정 (먼저!)

✅ **2026-10-16에 한 번 검증했고, 실제로 전방↔우측이 바뀌어 있어 교정했다.**
(교정 후: 전방=`FHH26070139`/cam2, 좌측=`FHH26070138`/cam1, 우측=`FHH26070137`/cam4,
후방=`FHH26070140`/cam3 — `01_Hardware/HW_구성도_개발보고서용.md` §6)

그래도 **장착을 다시 하거나 케이블을 다시 꽂았다면 매번 확인할 것.** 여기가 틀리면
박스→방위 환산이 90°·180° 단위로 통째로 틀어지는데, 코드는 아무 오류도 내지 않는다.

- [ ] `live_demo.py` 또는 `preflight_view.py`를 띄우고, **각 방향에서 손을 흔들어**
      전/좌/후/우 화면이 맞게 뜨는지 확인 (실내에서 어두우면 `--max-exposure 40`)
- [ ] 어긋나면 **세 군데를 같이** 고친다 — `live_demo.CAMERA_SERIAL`,
      `live_demo.CAMERA_INDEX_FALLBACK`, `camera_bearing.CAMERA_CALIB_ID`.
      내부 파라미터(fx)는 방향이 아니라 물리 카메라를 따라가므로 한쪽만 고치면 안 된다

### D-2. 화각 — 이번 장착에서 가장 불확실한 값

캘리브레이션 fx 기준 **52.7°** vs 하드웨어 문서의 2.8mm 렌즈 **≈103°**. 둘 다 맞을 수 없다.

- [ ] 전방 정중앙 10m 표적이 **화면 가로 정중앙**에 오는가
      → 벗어난 픽셀 `d`로 `trim ≈ -atan(d / fx)` (fx는 `--report`가 찍어준다)
- [ ] 표적을 **화면 가장자리에 겨우 걸치는 위치**까지 옮기고 그때의 방위를 잰다
      (`python3 lidar_calibrate.py --monitor`가 실시간으로 찍어준다) → **그 방위 × 2 = 화각**
- [ ] 결과를 `config/camera_mount.json`의 `hfov_deg` · `yaw_trim_deg`에 기입
- [ ] `python3 camera_bearing.py --report` 다시 실행 — 공백 구역이 사라졌는지 / 여전한지 기록

> 52.7°가 맞다면 카메라가 방위를 37°씩(합계 149°) 비워둔다. 그 구역의 대상은 YOLO로 지목할
> 수 없고 화면에 "소리 방향"으로만 뜬다 — **고장이 아니라 화각 문제**다. 혼동하지 말 것.

## E. 정지 상태 통합 — 최종 경로 확인 (20분)

젯슨까지 띄운다. 종료는 반드시 Ctrl+C (SSH 창을 그냥 닫으면 마이크를 계속 점유한다 →
`pkill -f "[j]etson_audio_sender\.py"`).

```bash
# 젯슨
python3 -u jetson_audio_sender.py --host 192.168.10.1 \
        --svm-path ~/owlmirror/03_Audio_Classification/model_outputs/panns_svm/best.pt
# 노트북
python3 live_demo.py --fullscreen --monitor HDMI-1-0
python3 monitor_rx.py --seconds 30          # (별 창) 링크 상태만 따로 보고 싶을 때
```

- [ ] 콘솔 시작 줄에 **실측한 장착값**이 찍힌다 (기본값 경고가 뜨면 C-3이 저장 안 된 것)
- [ ] 소리를 내면 해당 방향 카메라로 전환되고 배너가 뜬다
- [ ] **아는 거리(10m / 20m)에 세운 차량** — 화면 거리 오차 ±1m 이내
- [ ] 영상 위 박스 아래 **거리 판**이 뜨고, 보조 줄이 **"카메라 지목 · 라이다"**
- [ ] 콘솔의 `라이다: 방위` ↔ `카메라: 방위` 가 1~2° 안에서 일치
      (꾸준히 벌어지면 D-2로 돌아간다)
- [ ] **옆 차선에 다른 차를 세워둔 채**, 지목한 차의 거리가 나오는가 ← 이 구조의 핵심
- [ ] 걸어서 다가가면 `접근 x m/s`가 양수, 멀어지면 음수
- [ ] 비어 있는 방향에 점 클러스터가 뜨지 **않는다**
- [ ] 6m 안으로 들어가면 숫자 대신 "6m 이내 · 사각지대"

### 마이크 오프셋 역산 (라이다 보정이 끝난 뒤에만)

```bash
python3 lidar_calibrate.py --audio-offset --samples 20
```

- [ ] 여러 방향에서 20건 수집, 차이 중앙값 기록 (표준편차 10° 넘으면 주변을 비우고 재측정)
- [ ] 젯슨 `--mount-offset`에 **현재 값 + 차이 중앙값** 적용 후 재확인

## G. 주행 시험 (30분) — 정지 시험을 전부 통과한 뒤에만

- [ ] 데드캣 장착 (풍절음)
- [ ] **접근 속도는 상대 속도다** — 주행 중에는 정지한 가드레일·주차 차량도 자차 속도만큼
      "접근"으로 보인다. 정지 시험 결과와 비교해 이 현상이 실제로 보이는지 확인
- [ ] 노면·연석이 물체로 올라오지 않는가 → 올라오면 `min_object_height_m`을 0.35~0.4로
- [ ] 주행 소음에서 오경보 빈도 → `--min-db` 재조정 값 기록
- [ ] 터널·그늘·역광에서 카메라가 뭉개지지 않는가 (노출 상한 8ms)
- [ ] 햇빛 아래 화면 가독성 — `--theme day` / `night` 비교
- [ ] 독 구간 대역폭: LiDAR 유실률이 정지 때와 비슷한가 (`monitor_rx.py`, 카메라 30fps 상한 유지)

## 알려진 함정 (같은 데서 두 번 막히지 않도록)

| 증상 | 원인·조치 |
|---|---|
| 젯슨 실행이 멈춘 듯 | SSH stdout 버퍼링 → `python3 -u` |
| "마이크 못 찾음" | 이전 실행이 점유 중 → `pkill -f "[j]etson_audio_sender\.py"` |
| 핑은 되는데 패킷 없음 | 젯슨·노트북 IP 충돌(루프백 응답) |
| **모든 방향이 6~8m로 나옴** | 지면 미제거 = 높이값 과대 → C-1 재측정 |
| 카메라가 4.5fps | 자동노출이 노출시간을 끝까지 올림 → 노출 상한 확인 |
| 화면 위아래 흰 띠 | OpenCV Qt 툴바 → `WINDOW_GUI_NORMAL` (이미 적용됨) |
| BEV 좌우 반전 | 각도 규약(시계/반시계) 변환 누락 |
| 거리 판에 계속 "거리 확인 중" | 추적이 확정 안 됨 — 그 방위에 점이 모자라거나(멀다) 창이 너무 좁다 |
| 거리 판이 항상 "소리 방향" | YOLO가 대상을 못 잡음 또는 **화각 밖**(D-2 참고) |
