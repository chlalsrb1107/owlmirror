## 01. PANNs 임베딩을 SVM으로 5클래스 분류

**젯슨 · 음향 분류** · `03_Audio_Classification/code/realtime_classify.py` — load_panns_model() · classify()

1초 오디오를 PANNs Cnn14의 2048차 임베딩으로 바꾼 뒤, 그 벡터만 SVM에 넣어 경적·사이렌·오토바이를 가른다. 소리 인식의 본체다.

```python
def load_panns_model(ckpt_path: Path, device: str = "auto"):
    """PANNs Cnn14를 로드하고 지정 장치로 옮긴다."""
    from panns_inference.models import Cnn14

    model = Cnn14(sample_rate=16000, window_size=512, hop_size=160,
                  mel_bins=64, fmin=50, fmax=8000, classes_num=527)
    ckpt = torch.load(ckpt_path, map_location="cpu", weights_only=False)
    model.load_state_dict(ckpt["model"])
    model.eval()

    dev = resolve_device(device)      # "auto" -> CUDA가 있으면 cuda
    model.to(dev)                     # ← 이 한 줄이 없어 젯슨에서 CPU로 돌고 있었다
    if dev == "cuda":
        with torch.no_grad():         # 첫 CUDA 호출 지연을 미리 태워 없앤다
            model(torch.zeros(1, SR, device=dev))
        torch.cuda.synchronize()
    return model


def classify(panns_model, clf, class_names, audio_f32: np.ndarray):
    device = next(panns_model.parameters()).device
    audio_t = torch.from_numpy(audio_f32).unsqueeze(0).to(device)
    with torch.no_grad():
        # 527클래스 출력이 아니라 2048차 embedding을 특징으로 쓴다.
        # SVM(sklearn)은 CPU numpy만 받으므로 임베딩은 다시 내려받는다.
        embedding = panns_model(audio_t)["embedding"].cpu().numpy()
    scores = clf.decision_function(embedding)[0]
    order = np.argsort(scores)[::-1]
    return [(class_names[i], float(scores[i])) for i in order]
```

**설명**

- 527개 클래스 분류 출력이 아니라 **중간 임베딩**을 특징으로 쓴다. 대규모 사전학습이 만든 표현을 그대로 빌려오고 우리 5클래스는 가벼운 SVM으로만 학습하므로, 수집 데이터가 적어도 된다.
- `model.to(dev)` 한 줄이 성능을 갈랐다. `torch.cuda.is_available()`가 True인 것과 모델이 GPU에 올라가는 것은 별개여서, 이 줄이 없던 동안 CUDA가 있는 젯슨에서도 추론이 CPU에서 돌았다. 추가 후 **278ms → 78ms**, 전송 주기 1.220초 → 1.024초.
- 첫 CUDA 호출은 커널 컴파일·메모리 할당 때문에 유독 느리다. 로딩 직후 0 텐서로 한 번 태워 "첫 감지만 늦는" 현상을 없앤다.
- `decision_function` 값은 신뢰도로 쓰지 않는다. sklearn 다중클래스 OvR 구조상 확신 있는 예측이면 클래스와 무관하게 늘 4.2 근처가 나와 변별력이 없다 — 오경보 차단은 음량으로 한다(03장).

**실측·설정값** — 사이렌 검출률 83% · 입력 16 kHz · 1.0초 · 추론 78 ms (CUDA) · 임베딩 2048차

## 02. 수음과 방향 읽기를 같은 구간에서 동시에

**젯슨 · 수음 루프** · `08_Video_Demo/code/jetson_audio_sender.py` — run_live() 주기 루프

1.0초를 모으는 그 동안 방향(DoA)을 8회 읽는다. 지금 분류하는 소리와 방향이 반드시 같은 시간 구간에서 나오게 하려는 구조다.

```python
n_samples = int(seconds * clf.SR)                       # 1.0초 창 = 16,000 샘플
chunks_per_doa = max(1, int(n_samples / clf.CHUNK / DOA_SAMPLES_PER_WINDOW))

while True:
    t_capture_start = time.time()
    frames, collected, doa_samples, n_chunk = [], 0, [], 0
    while collected < n_samples:
        raw = stream.read(clf.CHUNK, exception_on_overflow=False)
        chunk = np.frombuffer(raw, dtype=np.int16).reshape(-1, clf.CHANNELS)
        frames.append(chunk[:, clf.MIC_CHANNEL_INDEX])  # ch0 = 보드 AEC 처리 채널
        collected += chunk.shape[0]
        # 수음하는 동안 DoA를 같이 읽는다 — 지금 분류하는 그 소리의 방향이 된다
        if n_chunk % chunks_per_doa == 0:
            try:
                doa_samples.append(float(tuning.direction))    # 구간당 8회
            except Exception:
                pass                                    # 한 번 실패해도 나머지로 계속
        n_chunk += 1
    t_center = t_capture_start + seconds / 2.0          # 스펙상 t는 구간의 '중심' 시각

    mono = np.concatenate(frames)[:n_samples].astype(np.float32) / 32768.0
    # dBFS. 완전 무음이면 log(0)이 되므로 바닥을 -90dB로 깐다.
    rms_db = 20.0 * math.log10(
        max(float(np.sqrt(np.mean(mono ** 2))), 10 ** (-90 / 20)))
    results = clf.classify(panns_model, svm, class_names, mono)
    top_class, top_score = results[0]
```

**설명**

- ReSpeaker는 6채널로 열리지만 분류에는 **ch0(보드에서 AEC 처리된 채널)**만 쓴다. 나머지는 방향추정용 원시 채널이라 분류 특징으로는 더 나쁘다.
- 창 길이 1.0초는 실측으로 정했다. 0.5초로 줄이면 주기는 빨라지지만 **사이렌 검출률이 83% → 35%**로 무너진다 — 사이렌은 주파수가 오르내리는 한 주기가 1~2초라 0.5초 창에는 특징이 반밖에 안 담긴다.
- `t`는 구간 시작이 아니라 **중심** 시각이다. 노트북이 "수음~화면 표시 지연"을 계산하는 기준이 된다.
- 음량은 dBFS로 재고 무음에서 `log(0)`이 되지 않게 −90 dB 바닥을 깐다. 이 한 값이 뒤의 오경보 차단·방향 신뢰·근접 판정에 모두 쓰인다.

**실측·설정값** — 실측 주기 1.024초 · 분석 창 1.0초 / 16,000 샘플 · DoA 8회 / 창 · ch0 (AEC)

## 03. 방향 하나가 아니라 방향과 흩어짐을 함께 보낸다

**젯슨 · 방향 신뢰도** · `08_Video_Demo/code/jetson_audio_sender.py` — circular_stats() · 전송 판정

DoA를 한 번만 읽으면 튄 값이 그대로 화면 방향이 된다. 8회를 원형 평균으로 묶고, 흩어진 정도로 그 방향을 믿을지 말지까지 정해서 보낸다.

```python
def circular_stats(angles_deg):
    """각도 목록의 (원형 평균, 원형 표준편차). 0/360 경계를 올바르게 처리한다.

    산술 평균을 쓰면 350°와 10°의 평균이 180°(정반대!)가 된다.
    """
    if not angles_deg:
        return 0.0, 180.0
    xs = sum(math.cos(math.radians(a)) for a in angles_deg)
    ys = sum(math.sin(math.radians(a)) for a in angles_deg)
    n = len(angles_deg)
    mean = math.degrees(math.atan2(ys, xs)) % 360.0
    r = math.hypot(xs, ys) / n        # 벡터 합의 길이 = 얼마나 한 방향에 모였나
    if r <= 1e-9:
        return mean, 180.0
    sd = math.degrees(math.sqrt(max(0.0, -2.0 * math.log(min(1.0, r)))))
    return mean, sd


# ---- 1주기 안에서 방향·불확실도·신뢰 여부를 한꺼번에 낸다 --------------------
raw_theta, spread = circular_stats(doa_samples)
theta = to_vehicle_frame(raw_theta, mount_offset)     # (raw - offset) % 360
sigma_out = max(sigma, min(spread, 60.0))             # BEV 부채꼴 폭 = 실측 흩어짐

# 읽은 값들이 모였고(spread) 소리가 실제로 있었나(rms). 하나라도 못 미치면
# 노트북은 그 방향으로 카메라를 돌리지 않는다.
theta_ok = spread <= DOA_MAX_SPREAD_DEG and rms_db >= DOA_MIN_DB   # 35°, -42dB
loud_enough = rms_db >= min_db                                     # -40dB

if top_class in ALERT_CLASSES and top_score >= min_score and loud_enough:
    pkt = sender.send(top_class, conf, top_score, theta, sigma_out, t_center,
                      rms_db, margin, theta_ok, top_class)
else:   # 배경음이거나 너무 조용함 — 방향은 의미 없으므로 0으로 보낸다
    pkt = sender.send("none", conf, top_score, 0.0, sigma_out, t_center,
                      rms_db, margin, False, top_class)
```

**설명**

- 각도는 산술 평균이 성립하지 않는다 — 350°와 10°의 평균이 **180°(정반대)**가 된다. 단위벡터로 더한 뒤 각도를 되찾아야 한다.
- 벡터 합의 길이 R이 곧 뭉침 정도다. 이를 표준편차로 바꿔 `sigma`로 보내면 BEV 부채꼴이 불확실할 때 저절로 넓어지고 확실할 때 좁아진다 — 정직한 표현이 된다.
- 실측 근거: 사이렌이 끊긴 구간에서 287·284·289로 안정적이던 값이 **222·79로 튀었다.** 흩어짐 ≤ 35°와 음량 ≥ −42 dB 두 조건이 이 구간을 걸러낸다.
- `theta_ok=False`면 노트북은 카메라를 돌리지도 방향을 그리지도 않는다. **잘못된 지목은 알려주지 않는 것보다 위험하다** — 청각장애인 운전자는 화면 말고 되짚을 경로가 없다.

**실측·설정값** — 방향 정밀도 σ 5~7° · 흩어짐 임계 35° · 방향 유효 −42 dBFS · 오경보 차단 −40 dBFS

## 04. 펌웨어 DoA를 USB로 읽어 카메라 4대에 배정

**방향 추정 · 카메라 배정** · `08_Video_Demo/code/doa_camera_select.py` — Tuning.direction · select_camera()

방향추정은 자체 구현 TDoA가 아니라 ReSpeaker 펌웨어가 계산한 값을 USB 제어전송으로 직접 읽어 쓴다. 그 각도가 곧 어느 카메라를 띄울지를 결정한다.

```python
VENDOR_ID, PRODUCT_ID = 0x2886, 0x0018
DOAANGLE_ID = 21          # ReSpeaker 공식 PARAMETERS 테이블의 DOAANGLE 레지스터


class Tuning:
    """ReSpeaker 4 Mic Array v2.0 USB Tuning 인터페이스에서 DOAANGLE만 읽는 최소 구현."""

    def __init__(self, dev):
        self.dev = dev

    @property
    def direction(self) -> int:
        import usb.util

        cmd = 0x80 | 0x40                       # read + int type
        response = self.dev.ctrl_transfer(
            usb.util.CTRL_IN | usb.util.CTRL_TYPE_VENDOR
            | usb.util.CTRL_RECIPIENT_DEVICE,
            0, cmd, DOAANGLE_ID, 8, CTRL_TIMEOUT_MS,
        )
        value, _ = struct.unpack(b"ii", response.tobytes())
        return value


CAMERA_RANGES = {              # 차량 전방(북) 0°, 반시계 + / 90°씩 4분할
    "front": (-45, 45),        # 북
    "left":  (45, 135),        # 서
    "rear":  (135, 225),       # 남 (기본 표시)
    "right": (-135, -45),      # 동
}


def select_camera(doa_deg: float, mount_offset_deg: float = MOUNT_OFFSET_DEG) -> str:
    """DoA 각도(0~359)를 받아 담당 카메라("front"/"left"/"rear"/"right")를 반환."""
    rel = (doa_deg - mount_offset_deg + 180) % 360 - 180   # -180~180 정규화
    for name, (lo, hi) in CAMERA_RANGES.items():
        if lo <= rel < hi:
            return name
    return "rear"                 # 경계값 예외 시 기본 표시 카메라로
```

**설명**

- 벤더 제어전송 1회(약 1 ms)로 `DOAANGLE` 레지스터(id = 21)를 읽는다. 응답 8바이트는 값 4 + 타입 4 구조라 `struct.unpack("ii")`로 풀어 앞쪽만 쓴다.
- 자체 구현 GCC-PHAT(`04_Sound_Localization/`)는 마이크 간격 보정이 안 돼 채택하지 않았다. 펌웨어 값은 2026-09-02 실장비에서 정상 동작을 확인했다.
- 좌표계는 **차량 전방 0°, 반시계 +**. 90°씩 4분할해 전/좌/후/우 카메라에 배정하고, 경계값 예외는 기본 표시 화면(후방)으로 떨어뜨려 화면이 비는 경우를 없앤다.
- `MOUNT_OFFSET_DEG`는 젯슨이 이미 적용해 차량 좌표계로 보내므로, 노트북에서는 반드시 `0.0`으로 호출한다. 두 번 적용하면 방향이 통째로 어긋난다.

**실측·설정값** — VID 0x2886 · PID 0x0018 · 레지스터 id 21 · 제어전송 ≈ 1 ms · 90° × 4분할

## 05. 두 기기 사이에는 JSON 한 줄만 오간다

**젯슨 ↔ 노트북 링크** · `jetson_audio_sender.py · audio_receiver.py` — Sender.send() · Receiver._loop()/get_new()

영상도 점군도 이 링크를 넘지 않는다. 초당 약 1회, 분류 결과와 방향만 UDP로 던지고 수신측은 "가장 최근 한 건"만 들고 있는다.

```python
class Sender:                                    # ── 젯슨 (송신) ──
    def send(self, class_name, conf, score, theta, sigma, t_center,
             rms_db=-60.0, margin=0.0, theta_ok=True, raw_class=""):
        packet = {
            "seq": self.seq, "t": round(t_center, 3), "class": class_name,
            "conf": round(conf, 3),   "score":  round(score, 3),
            "theta": round(theta, 1), "sigma":  round(sigma, 1),
            "rms_db": round(rms_db, 1), "margin": round(margin, 3),
            "theta_ok": bool(theta_ok), "raw": raw_class,
        }
        self.sock.sendto(json.dumps(packet).encode("utf-8"), self.addr)
        self.seq += 1
        return packet


class AudioDetectionReceiver:                    # ── 노트북 (수신 스레드) ──
    def _loop(self):
        while not self._stop.is_set():
            data, _ = self._sock.recvfrom(RECV_BUFSIZE)   # (타임아웃 처리 생략)
            packet = self._parse(data)           # JSON·필수필드 검사, 실패는 집계만
            if packet is None:
                continue
            now = time.time()
            with self._lock:
                self._track_seq(packet)          # seq 건너뜀 = 유실 개수
                self._track_skew(packet, now)    # 젯슨과의 시계 차이
                age = now - packet["t"]
                if abs(self._skew) < CLOCK_SKEW_WARN and age > MAX_PACKET_AGE:
                    continue                     # 밀려 도착한 오래된 패킷은 버린다
                self._latest = packet

    def get_new(self):
        """일부러 큐가 아니라 '최신 하나'만 준다 — 밀린 패킷을 순서대로 재생하면
        과거 상태가 뒤늦게 화면에 뜬다."""
        with self._lock:
            packet, self._latest = self._latest, None
            return packet
```

**설명**

- 이더넷 직결 위의 **UDP 단방향**(포트 9870). 재전송이 없는 대신 지연이 쌓이지 않는다 — 늦게 도착한 경고는 이미 틀린 경고다.
- 신뢰성은 재전송이 아니라 **계측**으로 확보한다. `seq` 건너뜀으로 유실을, `t`와 수신 시각의 차이로 시계 어긋남을 각각 집계하고, 시계가 맞을 때만 오래된 패킷을 버린다.
- 수신은 큐가 아니라 **최신 1건**만 보관한다. 밀린 패킷을 순서대로 재생하면 이미 지나간 상황이 뒤늦게 화면에 뜬다.
- 무거운 데이터(카메라 4채널 305 MB/s, LiDAR 점군)는 전부 노트북 한 프로세스 안에 머물러 프로세스 경계를 넘지 않는다. 경계를 넘는 것이 이 한 줄뿐이라 ROS2를 도입하지 않았다.

**실측·설정값** — 300+ 패킷 유실 0 · UDP 9870 · 단방향 · 페이로드 ≈ 180 B · 192.168.10.2 → .1

## 06. 소리 방향을 점군에서 되짚어 거리를 확정

**노트북 · 거리 확정** · `08_Video_Demo/code/lidar_distance_match.py` — filter_ground() · nearest_cluster() · match_distance()

소리가 알려준 각도 창 안에서 지면을 걷어내고, 거리축으로 뭉친 첫 덩어리까지의 거리를 그 대상의 거리로 삼는다.

```python
def filter_ground(points: np.ndarray, mount_height_m: float = MOUNT_HEIGHT_M):
    """노면과 머리 위 구조물을 빼고 "도로 위 물체" 높이대의 점만 남긴다."""
    if points.shape[0] == 0:
        return points
    z = points[:, 2]              # z는 라이다 원점 기준 → 노면은 -mount_height 부근
    above_ground = z > (-mount_height_m + MIN_OBJECT_HEIGHT_M)
    below_canopy = z < MAX_OBJECT_HEIGHT_M
    return points[above_ground & below_canopy]


def nearest_cluster(ranges, gap_m=CLUSTER_GAP_M, min_points=MIN_CLUSTER_POINTS):
    """거리값들을 덩어리로 묶어 가장 가까운 "충분히 큰" 덩어리를 돌려준다."""
    ordered = np.sort(ranges)
    splits = np.where(np.diff(ordered) > gap_m)[0] + 1
    for group in np.split(ordered, splits):      # np.split은 가까운 순서를 유지한다
        if group.size >= min_points:
            # 대표거리는 최솟값이 아니라 중앙값 — 노이즈 한 점이 거리를 못 끌어당기게
            return float(np.median(group)), int(group.size)
    return None


def match_distance(points, theta_deg, angle_margin_deg=DEFAULT_ANGLE_MARGIN_DEG,
                   blind_radius_m=BLIND_RADIUS_M, mount_height_m=MOUNT_HEIGHT_M):
    rel = (points[:, 4] - theta_deg + 180) % 360 - 180
    candidates = points[np.abs(rel) <= angle_margin_deg]     # ① 소리 방향 각도 창
    if candidates.shape[0] < MIN_POINTS:
        return None
    candidates = filter_ground(candidates, mount_height_m)   # ② 지면·천장 제거
    if candidates.shape[0] < MIN_POINTS:
        return None
    found = nearest_cluster(candidates[:, 3])                # ③ 거리축 클러스터링
    if found is None:
        return None
    distance, n_points = found
    if distance < blind_radius_m:                            # ④ 6m 이내 = 사각지대
        return {"distance_m": None, "blind": True, "points": n_points}
    return {"distance_m": distance, "blind": False, "points": n_points}
```

**설명**

- 네 단계로 좁힌다 — **① 소리 방향 각도 창 → ② 지면·천장 제거 → ③ 거리축 클러스터링 → ④ 가장 가까운 유효 덩어리.** 각 단계마다 점이 모자라면 "위치 미확정"으로 즉시 빠진다.
- 대표거리는 최솟값이 아니라 **중앙값**이다. 최솟값을 쓰면 노이즈 한 점이 거리를 통째로 끌어당긴다.
- 이전 구현은 "6 m 밖 점들의 최솟값"을 그대로 썼는데 지면이 섞여 들어와 실제로는 항상 6.0 m 근처가 나왔다. 지면 제거와 클러스터링을 넣어 고친 부분이다.
- VLP-16이 루프랙 최상단에 있어 **반경 6 m는 물리적 사각지대**다. 그 안의 물체는 거리를 주지 못하고 `blind=True`로만 보고하며, 6 m 밖에 다른 물체가 있어도 가까운 쪽을 우선한다.

**실측·설정값** — 사각 반경 6 m · 753.6 pps · 유실 0.1% · 마운트 높이 1.7 m · VLP-16 · 16채널

## 07. 소리마다 운전자가 알아야 할 것이 다르다

**노트북 · 판정 규칙** · `08_Video_Demo/code/alert_policy.py` — AlertPolicy — 경적 · 사이렌 · 오토바이

세 클래스가 같은 규칙을 쓰지 않는다. 경적은 크기와 반복을, 사이렌은 양보 의무를, 오토바이는 "보이나 / 가까워지나"를 본다.

```python
LOUD_NEAR_DB = -26.0    # 이보다 크면 "바로 옆" — 라이다가 못 보는 6m 안을 소리로 메운다

    def horn_accepts(self, theta, rms_db, now=None):
        """동시다발 경적 중 이 경적이 배너를 차지할 자격이 있는가."""
        now = time.time() if now is None else now
        if self._horn_theta is None or now - self._horn_at > HORN_HOLD_SEC:
            return True                                      # 유지 중인 경적 없음
        if now - self._horn_at <= HORN_LATCH_SEC:            # 1.5초 = 같은 사건
            return rms_db > (self._horn_db if self._horn_db is not None else -999.0)
        return True                                          # 래치 후 = 새 사건

    def horn_level(self, theta, rms_db, now=None):
        ...                                   # 12초 창으로 history 정리 후 append
        repeats = sum(1 for _, a in self._horn_history
                      if _angle_close(a, theta, HORN_REPEAT_ANGLE_DEG))   # ±40°
        near = AlertPolicy.is_near(rms_db)                   # rms_db >= -26dB
        # 같은 방향에서 두 번째면 나를 향한 신호로 보고, 아주 가까우면 그것만으로 경고
        level = "경고" if (repeats >= HORN_REPEAT_COUNT or near) else "주의"
        return level, repeats, near

    @staticmethod
    def siren_level(match, rms_db=-99.0):
        """긴급차량은 위치 확정 여부와 무관하게 항상 경고 — 양보 의무."""
        if match is not None and match["blind"]:
            return "경고", None, True
        if match is not None:
            return "경고", match["distance_m"], False
        return "경고", None, AlertPolicy.is_near(rms_db)

    @staticmethod
    def motorcycle_level(match, detected, rms_db, score=0.0):
        """잡았나(경고·추적) / 가까워지나(경고·근접) / 모르나(주의) 셋뿐이다."""
        if detected:
            if match is not None and match["blind"]:
                return "경고", None, True, "사각지대"
            distance = match["distance_m"] if match else None
            return "경고", distance, False, "위치 추적"
        if match is not None and match["blind"]:
            return "경고", None, True, "사각지대"
        if AlertPolicy.is_near(rms_db):     # 안 보이는데 배기음이 커진다 = 접근 중
            return "경고", None, True, "근접"
        return "주의", None, False, "사각지대 위험"
```

**설명**

- **경적** — 여러 방향에서 동시에 잡히면 1.5초 래치 안에서는 **더 큰 소리만** 배너를 가져간다. 같은 방향(±40°)에서 12초 안에 두 번이면 나를 향한 신호로 보고 주의 → 경고로 올린다.
- **사이렌** — 위치 확정 여부와 무관하게 **항상 경고**. 긴급차량은 양보 의무가 있어 운전자가 반드시 알아야 한다. 라이다가 잡히면 거리가 덧붙을 뿐 단계는 바뀌지 않는다.
- **오토바이** — 안 보이는데 배기음이 커지면(≥ −26 dBFS) 경고까지 올린다. 라이다·카메라가 둘 다 못 보는 근접 사각을 소리로 메우는 이 경로가 시스템의 차별점이다.
- 임계값은 마이크 입력 기준 상대값(dBFS)이지 절대 음압이 아니다. 차량 장착 후 실제 주행 소음에서 재보정해야 한다.

**실측·설정값** — 근접 판정 −26 dBFS · 경적 래치 1.5초 · 유지 4.0초 · 반복 ±40° / 12초 / 2회

## 08. 감지 한 건이 화면까지 가는 경로

**노트북 · 통합** · `08_Video_Demo/code/live_demo.py · alert_policy.py` — detection_worker() · priority_rank()

수신 → 카메라 선택 → YOLO 검출 → LiDAR 매칭 → 단계 판정을 한 스레드가 순서대로 처리하고, 동시 감지는 우선순위로 정렬한다.

```python
def detection_worker(state, receiver, detector, policy):
    last_camera = "rear"                     # 방향을 못 믿을 때 되돌아갈 기준 화면
    while True:
        packet = receiver.get_new()
        if packet is None:
            time.sleep(POLL_INTERVAL)
            continue
        top_class = packet["class"]
        if top_class not in CAMERA_TRIGGER_CLASSES:
            continue                         # none·배경음 — 유지시간이 지나면 풀린다

        doa = packet["theta"]                # 젯슨이 이미 차량 좌표계로 보냈다
        rms_db = float(packet.get("rms_db", -60.0))

        # 더 큰 경적에 밀리면 카메라 전환도 YOLO도 돌리지 않는다 (헛일 제거)
        if top_class == "car_horn" and not policy.horn_accepts(doa, rms_db):
            continue

        theta_ok = bool(packet.get("theta_ok", True))
        if theta_ok:
            camera = select_camera(doa, mount_offset_deg=0.0)   # 오프셋 이중적용 방지
            last_camera = camera
        else:
            camera = last_camera             # 못 믿는 방향으로는 화면을 돌리지 않는다

        detection = (run_detection(detector, camera, top_class)      # YOLO
                     if top_class in DETECTION_CLASSES else None)
        level, distance, blind, detail = decide_alert(
            policy, top_class, doa, detection, rms_db, score, theta_ok)
        state.trigger(camera, top_class,
                      LOC_LABEL_KO[camera] if theta_ok else "방향 미확정",
                      detection, level, distance, blind,
                      theta=doa if theta_ok else None,
                      sigma=float(packet.get("sigma", 12.0)), detail=detail)


def priority_rank(class_name, level, blind) -> int:
    """물리적 충돌 임박 > 법적 의무 > 신호. 숫자가 작을수록 우선순위 높음."""
    if class_name == "motorcycle" and blind:
        return 1                             # 사각지대 — 충돌 최임박
    if class_name == "motorcycle" and level == "경고":
        return 2                             # 영상으로 확인·추적 중
    if class_name == "siren":
        return 3                             # 항상 경고, 응급차량 양보 의무
    if class_name == "car_horn" and level == "경고":
        return 4                             # 같은 방향 반복 = 나를 향한 신호
    if class_name == "car_horn":
        return 5
    return 6                                 # 오토바이 · 주의
```

**설명**

- 무거운 일(YOLO 추론, 라이다 매칭)은 렌더 루프와 분리된 이 스레드에서만 한다. 덕분에 화면은 프레임당 **6~8 ms**를 유지한다.
- 판정 전에 값싼 거절을 먼저 한다 — 배경음이면 곧바로 빠지고, 더 큰 경적에 밀리면 카메라 전환도 YOLO도 돌리지 않는다.
- 방향을 못 믿으면 직전 카메라를 유지하고 **라이다도 조회하지 않는다.** 틀린 각도로 점군을 뒤지면 엉뚱한 방향에 그럴듯한 거리 숫자를 붙이게 된다.
- 동시 감지 순서는 **물리적 충돌 임박(오토바이 사각) > 법적 의무(사이렌) > 신호(경적)**. 배너는 1위만 차지하고, BEV 지도에는 감지된 것을 전부 그린다.

**실측·설정값** — 렌더 6~8 ms/프레임 · 트리거 클래스 3종 · YOLO 신뢰도 하한 적용 · 우선순위 6단계

## 09. 각도 규약 통일과 거리 반비례 점멸

**화면 · BEV 렌더** · `08_Video_Demo/code/bev_render.py` — _screen_angle() · to_px() · alert_period()

주 사용자가 청각장애인 운전자다. 경고음은 도달하지 않으므로 화면이 유일한 전달 경로이고, 급할수록 빨리 깜빡여 주변시야에 걸리게 한다.

```python
def _screen_angle(theta_ccw_deg):
    """시스템 theta(전방 0°, 반시계 +) → 화면 각도(전방 0°, 시계 +).
    각도 규약이 두 개라 여기 한 곳에서만 뒤집는다 — 빠뜨리면 BEV가 통째로 좌우 반전된다."""
    return -np.asarray(theta_ccw_deg, dtype=np.float64)


def radius_px(dist_m):
    """거리 → 픽셀 반지름. sqrt 스케일이라 가까운 쪽이 넓게 잡힌다(근접이 더 중요)."""
    d = np.clip(np.asarray(dist_m, dtype=np.float64), 0.0, RANGE_MAX_M)
    return np.sqrt(d / RANGE_MAX_M) * RMAX


def to_px(theta_ccw_deg, dist_m):
    """(theta, 거리) → (x, y) 픽셀. 스칼라/배열 모두 지원."""
    a = np.radians(_screen_angle(theta_ccw_deg) - 90.0)   # -90 = 화면 위쪽이 전방
    r = radius_px(dist_m)
    return CX + np.cos(a) * r, CY + np.sin(a) * r


def alert_period(distance, blind):
    """경고 점멸 주기(초). 가까울수록 빠르다 — 주변시야에 걸리게 하려는 것."""
    if blind or distance is None:
        return 0.3                                   # 사각지대·미확정 = 가장 급함
    return min(1.2, max(0.3, distance / 25.0 * 1.2))  # 25m에서 1.2초


def pulse_level(period):
    """0~1 삼각파. 사각형파로 깜빡이면 눈이 피로해 밝기를 부드럽게 오르내린다."""
    return abs((time.time() % period) / period * 2.0 - 1.0)
```

**설명**

- 시스템 각도는 반시계 +인데 UI 목업 SVG는 시계 +다. `_screen_angle()` **한 곳에서만** 부호를 뒤집는다 — 다른 곳에서 또 뒤집으면 BEV가 통째로 좌우 반전된다.
- 거리 → 반지름은 **sqrt 스케일**이다. 가까운 쪽이 화면에서 넓게 잡혀, 근접한 위험이 더 크게 보인다.
- 점멸 주기가 거리에 반비례한다(25 m에서 1.2초, 사각지대 0.3초). 사각형파 대신 **삼각파**로 밝기를 오르내려 오래 봐도 눈이 덜 피로하다.
- BEV는 마커가 아니라 **LiDAR 실제 리턴 포인트**로 그린다. 매칭이 확정되면 색 클러스터, 미확정이면 σ만큼의 부채꼴이라 확신의 정도가 그림에 그대로 드러난다.

**실측·설정값** — 점멸 0.3 ~ 1.2초 · 1920 × 1080 전체화면 · 렌더 6~8 ms · 표시 반경 RANGE_MAX
