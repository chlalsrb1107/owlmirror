# 올빼미러 (OwlMirror)

소리로 다가오는 위험을 화면으로 보여주는 운전 보조 시스템입니다.

사이렌, 경적, 오토바이 배기음을 마이크 어레이로 듣고 그 방향을 계산합니다. 해당 방향의
카메라를 자동으로 띄우고, 화면 안에서 YOLO가 대상을 찾아내면 그 물체까지의 거리를 LiDAR로
재서 영상 위에 함께 표시합니다.

소리에서 화면까지 이어지는 파이프라인 전 단계가 구현되어 있고, 차량에 실제로 장착한
상태입니다. 장비 없이도 셀프테스트로 파이프라인 전체를 돌려볼 수 있습니다.

한이음 공모전 출품작입니다.

---

## 왜 만들었나

운전 중에 들어야 할 소리가 있습니다. 뒤에서 오는 구급차의 사이렌, 옆 차선의 경적, 차 사이로
끼어드는 오토바이 소리입니다. 청각장애인 운전자는 이 정보를 얻을 수 없습니다.

기존 보조 장치는 대부분 "소리가 났다"는 사실만 알려줍니다. 운전자가 정작 알아야 하는 것은
어느 쪽에서, 무엇이, 얼마나 가까이 오고 있는지입니다. 방향을 모르면 어느 거울을 봐야 할지
알 수 없고, 거리를 모르면 지금 피해야 하는지 판단할 수 없습니다.

올빼미러는 이 세 가지를 한 화면에 담는 것을 목표로 했습니다.

| 질문 | 담당 센서 |
|---|---|
| 어느 쪽인가 | 마이크 어레이 (방향 탐지) |
| 무엇인가 | 카메라 + YOLO 검출 |
| 얼마나 먼가 | LiDAR 거리 측정 |

주 사용자가 청각장애인 운전자이므로 경고음은 전달 수단이 될 수 없습니다. 화면이 유일한
경로이고, 이 전제가 UI 설계 전반의 기준이 되었습니다.

## 어떻게 동작하나

```
① 소리로 방향을 찾는다       ReSpeaker DoA → theta ± sigma        (σ 5~7°)
② 그 방향 카메라를 띄운다     select_camera(theta)                 (전/좌/후/우)
③ YOLO가 대상을 지목한다      구급차·오토바이 박스
④ 박스를 방위각으로 되돌린다   camera_bearing.bearing_from_box()    (창 ±3~12°)
⑤ 그 방위에서 거리를 잰다     LiDAR 추적 → 거리·접근 속도·실측 방위
⑥ 화면에 띄운다              영상 위 거리 표시 + BEV 지도 클러스터
```

세 센서가 각자 잘하는 일만 맡습니다. 소리는 어디를 볼지 정하고, 카메라는 그것이 무엇인지
판별하고, LiDAR는 거리를 잽니다.

핵심은 ③과 ④입니다. 소리 방향만으로 LiDAR를 조회하면 그 방향에 있는 아무 물체나 잡힙니다.
같은 각도 안에 주차된 차가 있으면 사이렌을 울리는 구급차 대신 주차 차량까지의 거리를
보여주게 됩니다. YOLO가 지목한 박스를 방위각으로 되돌려 조회 범위를 ±3~12°로 좁히면,
화면에 뜨는 숫자가 실제로 그 물체까지의 거리가 됩니다.

③이나 ④가 실패할 수도 있습니다. 대상이 가려졌거나 카메라 화각 밖일 때입니다. 이때는 소리
방향으로 조회하는 경로로 내려가고, 화면은 근거를 "카메라 지목" 또는 "소리 방향"으로
구분해 표시합니다. 같은 24m라도 신뢰도가 다르기 때문입니다.

### 시스템 구성

```
┌─ 젯슨 Orin Nano ─────────────┐        ┌─ 노트북 (Ubuntu 22.04) ────────────────┐
│  ReSpeaker 4 Mic Array v2.0  │        │  카메라 4대 (전/좌/후/우, 90° 간격)      │
│    → PANNs Cnn14 + SVM 분류  │        │  LiDAR Velodyne VLP-16                 │
│    → 펌웨어 DoA (방향)        │        │                                        │
│    → 음량(rms)·방향 신뢰도    │        │  UDP 수신 → 카메라 선택 → YOLO 검출     │
│                              │  UDP   │    → LiDAR 거리 매칭 → 화면 합성        │
│  JSON 한 줄만 전송 ──────────┼───────▶│                                        │
│  (영상·점군은 오가지 않는다)   │ 이더넷 │  BEV 지도 | 카메라 영상 반반 화면        │
└──────────────────────────────┘  직결  └────────────────────────────────────────┘
     192.168.10.2                             192.168.10.1
```

오디오 처리는 젯슨이, 영상과 거리 처리는 노트북이 맡습니다. 두 기기 사이를 오가는 것은
초당 약 1회의 JSON 한 줄뿐입니다. 카메라 4대의 305 MB/s와 LiDAR 점군은 노트북 안에
머물기 때문에 네트워크 부담이 없습니다.

```json
{"seq": 1234, "t": 1751250042.318, "class": "siren", "conf": 0.91,
 "theta": 194.0, "sigma": 7.4, "rms_db": -22.4, "theta_ok": true}
```

| 필드 | 설명 |
|---|---|
| `class` | `car_horn` / `siren` / `motorcycle` / `none` |
| `theta` | 차량 좌표계 방위각 (전방 0°, 반시계 +) |
| `sigma` | 방향 불확실성(도). 수음 구간 안 DoA 8회 읽기의 실측 흩어짐 |
| `rms_db` | 음량(dBFS). 오경보 차단과 근접 판정에 사용 |
| `theta_ok` | 방향 신뢰 여부. `false`면 카메라를 돌리지 않습니다 |

## 화면

왼쪽은 BEV(조감도) 지도, 오른쪽은 카메라 영상입니다.

BEV 지도는 아이콘 마커가 아니라 LiDAR가 실제로 받은 반사점을 그립니다. 거리가 확정된
대상은 색 클러스터로, 아직 미확정이면 방향만 부채꼴로, 6m 이내면 사각지대 구역으로
표시합니다. 자차 둘레에는 감지 방향으로 호가 켜집니다.

오른쪽 영상에서는 YOLO가 찾은 박스 바로 아래에 거리를 띄웁니다. 주행 중에 지도에서 점을
찾아 눈으로 환산할 시간은 없습니다. 운전자가 실제로 보는 것은 "저 구급차까지 24m"라는
영상 위의 숫자입니다.

화면 설계 원칙은 청각장애인 운전자를 기준으로 정리했습니다.

1. 소리로 보완할 수 있다고 가정하지 않습니다. 화면에 없는 정보는 전달되지 않은 정보입니다.
2. 정보마다 그림과 글자를 함께 줍니다. 종류는 아이콘과 이름, 방향은 회전 화살표와 "좌측".
3. 주변시야에 걸리게 합니다. 경고 단계에서는 테두리가 거리에 반비례하는 주기(0.3~1.2초)로
   깜빡입니다.
4. 읽는 시간을 줄입니다. 방향은 글자보다 화살표가, 위험도는 글자보다 색이 빠릅니다.

거리가 아직 확정되지 않았을 때는 자리를 비워두지 않고 "거리 확인 중"이라고 적습니다. 빈
자리는 "거리가 없다"로도 "센서가 못 본다"로도 읽히기 때문입니다.

화면 예시 14종: [`06_Display_Integration/ui_screens/`](06_Display_Integration/ui_screens/)
상세 사양: [`06_Display_Integration/ui_state_spec.md`](06_Display_Integration/ui_state_spec.md)

### 알림 규칙

소리마다 운전자가 알아야 할 내용이 다르므로 클래스별로 규칙을 나눴습니다.

| 소리 | 규칙 |
|---|---|
| 경적 | 동시 발생 시 가장 큰 소리 채택(1.5초 래치), 4초 유지. 같은 방향 ±40°에서 12초 안에 2회면 경고로 승격 |
| 사이렌 | 항상 경고. 긴급차량은 위치 확정 여부와 무관하게 알아야 합니다(양보 의무) |
| 오토바이 | 검출 성공이면 경고·위치 추적, 배기음이 커지면 경고·근접, 그 외에는 주의·사각지대 위험 |

동시에 여러 소리가 잡히면 배너는 하나만 띄우고 지도에는 전부 그립니다. 배너 우선순위는
다음과 같습니다.

```
오토바이 사각지대 > 오토바이 경고 > 사이렌 > 경적 반복 > 경적 1회 > 오토바이 주의
```

오토바이가 가장 위에 있는 이유는 충돌이 가장 임박한 상황이기 때문입니다. 사이렌은 양보
의무이고 경적은 신호이지만, 사각지대의 오토바이는 지금 피하지 않으면 부딪힙니다.

구현과 검증: [`08_Video_Demo/code/alert_policy.py`](08_Video_Demo/code/alert_policy.py)

## 구현 현황

파이프라인 6단계가 모두 구현되어 동작합니다. 2026-10-15에 마지막 단계인 LiDAR 거리 측정이
연결되면서 소리에서 화면까지 끊김 없이 이어졌습니다.

| 단계 | 기능 | 상태 |
|---|---|---|
| ① | 음향 분류 (PANNs Cnn14 + SVM, 5클래스) | 완료 |
| ② | 방향 탐지 (ReSpeaker DoA + 원형 통계로 불확실도 산출) | 완료 |
| ③ | 젯슨→노트북 UDP 링크 (JSON, 유실·시계 스큐 추적) | 완료 |
| ④ | 방향에 따른 카메라 자동 전환 (4대) | 완료 |
| ⑤ | YOLO 검출 + 박스→방위각 환산 | 완료 |
| ⑥ | LiDAR 거리 측정·추적 (거리, 접근 속도, 실측 방위) | 완료 |
| | 클래스별 알림 규칙·우선순위 | 완료 |
| | BEV 지도 + 카메라 반반 화면, 주·야간 팔레트 | 완료 |
| | 외장 디스플레이 전체화면 (해상도 자동 대응) | 완료 |
| | 차량 실장착 (루프랙 카메라 4대 + VLP-16, 업체 시공) | 완료 |
| | 현장 캘리브레이션 도구 (장착 높이·요 오프셋·마이크 오프셋) | 완료 |

### 하드웨어 없이 확인

장비 없이도 파이프라인 전체를 검증할 수 있습니다.

```bash
cd 08_Video_Demo/code
python3 pipeline_selftest.py                       # 파이프라인 전체 (약 15초)
python3 lidar_distance_match.py --selftest         # 거리 매칭·추적
python3 alert_policy.py         --selftest         # 알림 규칙
python3 camera_bearing.py       --selftest         # 박스→방위 환산
python3 lidar_calibrate.py      --selftest         # 캘리브레이션 추정
python3 bev_render.py --selftest --outdir /tmp/bev # 화면 14종 PNG
```

`pipeline_selftest.py`는 가짜 센서(합성 노면과 다가오는 차량, 가짜 젯슨 패킷)를 꽂고
`live_demo.py`의 실제 함수들을 그대로 돌립니다. 모듈별 테스트가 모두 통과해도 모듈 사이의
연결이 틀리면 화면에는 아무 오류 없이 잘못된 값이 뜹니다. σ를 넘기지 않아 조회 범위가 항상
최대로 열려 있거나, 거리 갱신이 표시 루프에 걸려 있지 않은 경우입니다. 그 연결 자체를
검증하는 것이 이 파일의 역할입니다.

### 차량에 올린 직후 (장착값 실측)

```bash
cd 08_Video_Demo/code
python3 lidar_calibrate.py --sectors                             # 패킷·방향 확인
python3 lidar_calibrate.py --height                              # 노면 반사로 장착 높이 역산
python3 lidar_calibrate.py --bearing --expect 0                  # 정면 10m 표적으로 요 오프셋
python3 lidar_calibrate.py --height --bearing --expect 0 --write # config/lidar_mount.json에 저장
python3 lidar_calibrate.py --audio-offset --samples 20           # 마이크 오프셋 역산
python3 camera_bearing.py  --report                              # 카메라 화각·커버리지
```

장착 위치가 바뀌면 이 과정을 거칩니다. 거리 계산이 장착 높이와 요 오프셋에 매여 있기
때문입니다. 높이 기준이 어긋나면 노면 반사가 "6~8m 앞 물체"로 남고, 요 오프셋이 어긋나면
다른 방향에 있는 물체의 거리가 소리 방향에 붙습니다. 도구가 노면 반사와 표적으로 두 값을
자동으로 역산해 설정 파일에 기록합니다.


`--monitor`를 주면 그 모니터의 해상도 그대로 렌더링하므로 다른 해상도의 차량 디스플레이에도
대응됩니다. LiDAR 장착값은 `08_Video_Demo/config/lidar_mount.json`에서 읽습니다. LiDAR
없이 화면만 볼 때는 `--no-lidar`를 줍니다.

실내에서 점검할 때는 기하가 달라 설정을 바꿔야 합니다. 주행용 기본값은 그대로 두고 별도
설정 파일과 플래그를 씁니다.

```bash
python3 live_demo.py --lidar-config 08_Video_Demo/config/lidar_mount.indoor.json \
                     --bev-range 12 --max-exposure 40
```

### 젯슨

```bash
python3 -u jetson_audio_sender.py --host 192.168.10.1 \
        --svm-path ~/owlmirror/03_Audio_Classification/model_outputs/panns_svm/best.pt
```

`-u`를 붙여야 합니다. SSH 파이프로는 stdout이 블록 버퍼링되어 출력이 보이지 않습니다.
종료는 Ctrl+C로 합니다. SSH 창을 그냥 닫으면 젯슨 쪽 파이썬이 살아남아 마이크를 계속
점유하고, 다음 실행이 "마이크 못 찾음"으로 실패합니다. 그때는
`pkill -f "[j]etson_audio_sender\.py"`로 정리합니다.

## 개발하면서 막혔던 것들

실장비 연동에서 실제로 겪은 문제들입니다. 대부분 오류 메시지 없이 조용히 잘못 동작했습니다.

| 증상 | 원인 |
|---|---|
| 젯슨 실행이 멈춘 것처럼 보임 | SSH 파이프 stdout 버퍼링. `python3 -u`로 해결 |
| 마이크를 못 찾음 | 이전 실행이 살아서 점유 중. `arecord -l`에서 `Subdevices: 0/1` |
| 핑은 되는데 패킷이 안 옴 | 젯슨과 노트북 IP가 겹쳐 루프백이 응답 |
| 모든 방향이 6.34m로 나옴 | LiDAR 지면 미제거. 1.7m/tan(15°)가 노면까지 거리 |
| 카메라가 4.5 fps | 자동노출이 노출시간을 223ms까지 올림. 50km/h에서 3.1m 모션블러 |
| 화면 위아래 흰 띠 | OpenCV Qt 백엔드 기본 툴바. `WINDOW_GUI_NORMAL`로 해결 |
| BEV 좌우 반전 | 각도 규약(시계 vs 반시계) 변환 누락 |
| 전방 영상이 우측에 뜸 | 카메라 배선 순서와 소프트웨어 배정 불일치 |

마지막 항목은 코드가 알아챌 방법이 없습니다. 배선과 설정이 어긋나도 모든 함수가 정상적으로
동작하고, 좌측 사이렌이 우측 화면에 떠도 오류가 나지 않습니다. 장착할 때마다 각 방향에서
손을 흔들어 확인하는 수밖에 없습니다.
