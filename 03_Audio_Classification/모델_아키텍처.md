# 음원 분류 모델 아키텍처

> ⚠️ 이전 버전(MobileNet-V3 Small, 4클래스 Mel-Spectrogram CNN)은 폐기됨. 이후 파이프라인 검증용으로
> **AST(Audio Spectrogram Transformer)** 10클래스 모델을 썼고, 한때 팀원이 학습한 5클래스 모델도
> "AST"로 문서화된 적이 있었으나 **실제로 체크포인트(`best.pt`)를 열어 확인한 결과 AST가 아니라
> PANNs `Cnn14` 임베딩 + SVM 분류기 조합**이었다 (2026-08-17 정정). 확정 모델은 이 PANNs+SVM 5클래스
> 모델. 배경: `00_Overview/현재_상태_요약.md` "음향 분류 모델 현재 상태" 절.

## 모델 개요

| 항목 | 내용 |
|---|---|
| 특징 추출기 | PANNs `Cnn14` (16kHz 입력 변형, 공식 사전학습 가중치 `Cnn14_16k_mAP=0.438.pth`, Zenodo 배포 — 파인튜닝 없이 그대로 사용, 마지막 은닉층 2048차원 임베딩만 특징으로 사용) |
| 파이프라인 검증용 모델(구버전, 히스토리) | AST 기반, UrbanSound8K 전체 10클래스로 파인튜닝, 검증 정확도 **91.0%** |
| 분류기 | sklearn `Pipeline(StandardScaler, SVC(C=3.0, class_weight='balanced'))`, 5-way |
| 실사용 모델 | **5클래스**: `car_horn / children_playing / engine_idling / siren / motorcycle` |
| val / test 정확도 | 98.0% / 89.5% (체크포인트 기록값, 재현 완전성 관련 캐비엇은 아래 참고) |
| 체크포인트 | `03_Audio_Classification/model_outputs/panns_svm/best.pt` (용량 문제로 git 미포함, 폴더 내 README 참고) |
| 의존 패키지 | `panns_inference`, `torchlibrosa` (pip 설치 필요) |

## 5클래스 구성 (의도된 설계)

단일 `background` 클래스 대신, 실제 도로 환경에서 흔한 비타겟 소음(`children_playing`, `engine_idling`)을 명시적으로 학습시켜 배경음 역할을 하도록 한 설계다.

| 클래스 | 판단 로직 상 역할 |
|---|---|
| `car_horn` | 경보 대상 (경적) |
| `siren` | 경보 대상 (긴급차량 사이렌) |
| `motorcycle` | 경보 대상 (오토바이 배기음) |
| `children_playing` | 비경보 (배경음) |
| `engine_idling` | 비경보 (배경음) |

가중치는 아직 이 저장소에 없으므로(용량 문제로 git 제외), 팀 내 공유 방법(예: 기존 `outputs_ast.zip` 방식처럼 별도 경로 안내)을 별도로 정리해야 한다.

## 체크포인트 구조

`realtime_classify.py`가 기대하는 SVM 체크포인트 포맷(`torch.load`로 로드, `03_Audio_Classification/model_outputs/panns_svm/best.pt`):

```python
ckpt = {
    "classifier": sklearn.pipeline.Pipeline,  # StandardScaler + SVC(C=3.0)
    "classes": [...],              # 5클래스 리스트
    "panns_checkpoint": "...",     # 학습 시 사용한 PANNs 체크포인트 경로 (참고용)
    "semantic_thresholds": {...},  # 미적용 — 아래 "알려진 제한사항" 참고
    "val_accuracy": 0.98, "test_accuracy": 0.895, ...
}
```

PANNs Cnn14 쪽은 별도로 공식 사전학습 가중치(`Cnn14_16k_mAP=0.438.pth`)를 로드하며, 파인튜닝하지 않고
그대로 특징 추출기로만 사용한다. 새 SVM 모델로 교체할 때는 `classifier`/`classes` 키 형식만 지키면
실행 스크립트 수정이 필요 없다.

## 추론 실행

실행 스크립트: `03_Audio_Classification/code/realtime_classify.py`

```
ReSpeaker 6ch 캡처 → ch0(AEC) 추출 → PANNs Cnn14 순전파(2048차원 임베딩) → SVM decision_function → top-k 점수 출력
```

- PANNs Cnn14 가중치가 로컬에 없으면 최초 실행 시 Zenodo에서 자동 다운로드 시도 (~340MB, 인터넷 필요)
- **CPU 추론 지연은 아직 미측정** — 참고로 이전 AST 모델은 3초 오디오 → 추론 약 3.9초(Jetson GPU 미인식, CPU만) 였음. Cnn14도 CNN이라 비슷한 병목이 재현될 가능성이 있어 실측 필요
- TensorRT 변환/양자화 아직 미적용 — Jetson 추론 최적화 필요 항목으로 남아있음
- 현재 코드 기본값(`--seconds 1.0 --interval 2.0`)이 인터페이스 스펙(초당 4회)과 어긋나 있어 정리 필요 (`00_Overview/현재_상태_요약.md` 참고)

## 알려진 제한사항 (재현 불완전한 부분)

- **`semantic_thresholds` 미적용**: 체크포인트에 클래스별 임계값(추정: AudioSet 클래스 게이팅용)이 있으나, 어느 AudioSet 인덱스에 매핑되는지 알려줄 학습/계산 스크립트가 없어 `realtime_classify.py`는 SVM 원시 예측만 사용한다. 학습 담당 팀원에게 스크립트 확인 요청 필요
- **확률(%) 대신 마진 점수**: SVC가 `probability=False`로 학습되어 `decision_function` 점수만 얻을 수 있음
- **멀티뷰 학습 가능성**: `embeddings.pt`(2-view)/`embeddings_v3.pt`(3-view)가 함께 전달됨 — 학습 시 클립당 여러 임베딩을 평균했을 가능성이 있으나, 실시간 추론은 캡처 윈도우당 단일 순전파만 수행. 학습·평가에 쓰인 정확한 방식과 다르면 체크포인트 기록 정확도(val 98.0%/test 89.5%)보다 실측치가 낮을 수 있음
