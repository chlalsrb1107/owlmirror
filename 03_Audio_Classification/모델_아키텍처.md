# 음원 분류 모델 아키텍처

> ⚠️ 이전 버전(MobileNet-V3 Small, 4클래스 Mel-Spectrogram CNN)은 폐기됨. 확정 모델은 **AST(Audio Spectrogram Transformer)**이며, 현재 팀원이 학습한 **5클래스** 모델을 사용 중이다. 배경: `00_Overview/현재_상태_요약.md` "음향 분류 모델 현재 상태" 절.

## 모델 개요

| 항목 | 내용 |
|---|---|
| 베이스 모델 | `MIT/ast-finetuned-audioset-10-10-0.4593` (HuggingFace `transformers`) |
| 파라미터 수 | 86.2M |
| 파이프라인 검증용 모델 | UrbanSound8K 전체 10클래스로 파인튜닝, 검증 정확도 **91.0%** |
| 실사용 모델 | **5클래스**: `car_horn / children_playing / engine_idling / siren / motorcycle` |
| 체크포인트 | `03_Audio_Classification/model_outputs/outputs_ast/best.pt` (345MB, 용량 문제로 git 미포함) |

## 5클래스 구성 (의도된 설계)

단일 `background` 클래스 대신, 실제 도로 환경에서 흔한 비타겟 소음(`children_playing`, `engine_idling`)을 명시적으로 학습시켜 배경음 역할을 하도록 한 설계다.

| 클래스 | 판단 로직 상 역할 |
|---|---|
| `car_horn` | 경보 대상 (경적) |
| `siren` | 경보 대상 (긴급차량 사이렌) |
| `motorcycle` | 경보 대상 (오토바이 배기음) |
| `children_playing` | 비경보 (배경음) |
| `engine_idling` | 비경보 (배경음) |

가중치는 아직 이 저장소에 없으므로(용량 문제로 git 제외), 팀 내 공유 방법(예: 기존 `outputs_ast.zip` 방식처럼 별도 경로 안내)을 별도로 정리해야 한다.

## 체크포인트 구조

`realtime_classify.py`가 기대하는 체크포인트 포맷(`torch.load`로 로드):

```python
ckpt = {
    "model_name": "MIT/ast-finetuned-audioset-10-10-0.4593",
    "class_names": [...],       # 5클래스 리스트
    "model_state_dict": ...,
    "best_acc": 0.xx,
}
```

`ASTConfig`의 `num_labels`/`id2label`/`label2id`를 `class_names` 길이·순서에 맞춰 구성한 뒤 `ASTForAudioClassification`에 가중치를 로드한다. 새 모델을 교체할 때도 이 포맷만 지키면 실행 스크립트 수정이 필요 없다.

## 추론 실행

실행 스크립트: `03_Audio_Classification/code/realtime_classify.py`

```
ReSpeaker 6ch 캡처 → ch0(AEC) 추출 → AST FeatureExtractor → AST 추론 → top-k 확률 출력
```

- **CPU 추론 지연(측정값)**: 3초 오디오 → 추론 약 3.9초 (Jetson 내장 GPU 미인식, CPU로만 동작)
- TensorRT 변환/양자화 아직 미적용 — Jetson 추론 최적화 필요 항목으로 남아있음
- 현재 코드 기본값(`--seconds 1.0 --interval 2.0`)이 인터페이스 스펙(초당 4회)과 어긋나 있어 정리 필요 (`00_Overview/현재_상태_요약.md` 참고)
