# 영상 파이프라인 — 카메라 영상의 BEV UI 통합

> ⚠️ 이전 버전(Jetson 단일 카메라 GStreamer 파이프라인 + OpenCV 전체화면 HUD 오버레이)은 폐기됨. 확정 설계는 **노트북에서 BEV(Bird's-Eye View) 지도를 주 화면으로 쓰고, 카메라 영상은 보조(PIP) 화면으로만 사용**하는 것이다. 주 사양 문서는 `06_Display_Integration/ui_state_spec.md`, 목업은 `06_Display_Integration/bev_mockup.html`이며 이 문서는 그 안에서 카메라 영상이 어떻게 통합되는지만 다룬다.

## 위치 격하 — 영상은 더 이상 주 화면이 아님

- 기존: 카메라 영상 + HUD 오버레이가 전체 화면
- 현재: **BEV 지도가 주 화면**, 카메라 영상은 "위치 확정 시" 또는 "경적 감지 시"에만 화면 우측 하단에 보조(PIP) 영상으로 자동 표시
- 어느 카메라를 표시할지는 소리 방향에 따라 자동 선택됨 (`05_Camera_Tracking/DoA_카메라_매핑.md`의 `select_camera()` 참고)

---

## 영상 소스 — ROS2 토픽 기반 (Jetson GStreamer 파이프라인 아님)

카메라는 Jetson이 아니라 **노트북에 직결**되며, ROS2 카메라 노드(`usb_cam` 또는 `v4l2_camera`)가 각 카메라의 프레임을 상시 퍼블리시한다.

```
/camera_front/image_raw
/camera_rear/image_raw
/camera_left/image_raw
/camera_right/image_raw
```

BEV UI(웹 기반 목업 `bev_mockup.html`을 실제 애플리케이션으로 확장하는 작업)가 이 토픽 중 선택된 하나를 구독해 PIP로 렌더링한다. 웹 기반으로 유지할 경우 `rosbridge_suite` + `roslibjs` 등으로 ROS2 토픽을 브라우저에 브릿지하는 방법이 필요하며, 네이티브 앱(예: `rclpy` 기반 Qt/PyQt)으로 갈 경우 토픽을 직접 구독하면 된다 — **프레임워크 선택은 아직 미정** (내일 회의 안건).

---

## HUD 오버레이 방식의 변화

기존 OpenCV 기반 코너 배너·나침반 오버레이 방식은 폐기되고, `ui_state_spec.md`의 4단계 상태(IDLE/표시/주의/경고)와 상단 알림 막대·테두리 빛 규칙으로 대체되었다. 클래스별 색상 매핑도 5클래스 모델(`car_horn/siren/motorcycle` = 경보, `children_playing/engine_idling` = 비경보) 기준으로 다시 정의해야 하며, 세부 색상·레이아웃은 `ui_state_spec.md`와 `bev_mockup.html`을 기준으로 한다.

## 남은 작업

- `bev_mockup.html`은 정적 인터랙티브 목업 — 실시간 ROS2 데이터(카메라 토픽, `/vehicle/candidates`, `/audio/detection`)와 연동되는 실제 동작 앱으로 전환 필요
- PIP 표시 트리거 조건(경적 감지 / 위치 확정)을 실제 `/audio/detection`, `/vehicle/candidates` 토픽 값과 연결하는 로직 구현
- 프레임워크 확정(웹앱 유지 + rosbridge vs 네이티브 앱)
