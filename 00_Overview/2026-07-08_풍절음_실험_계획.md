# 2026-07-08 실차 풍절음 실험 계획 (중간평가 메인 콘텐츠)

> [[2026-07-05_회의록]] 후속. 중간평가 보고서의 핵심 실험 콘텐츠로 쓸 예정이라 최대한 정량적/재현 가능하게 설계함. 실험 당일(수요일) 전에 이 문서를 다시 열어 세부사항을 확정할 것.

---

## 전제: 마이크 하드웨어 사실 확인

- 실제 하드웨어는 **ReSpeaker Mic Array v2.0** — 독립형 USB 원형 퍽(puck), **지름 70mm, 두께 13.3mm**, 4개 마이크가 원판 둘레에 배치, 12개 LED도 둘레 배치
- (라즈베리파이용 사각형 HAT 보드 "ReSpeaker 4-Mic Array for Raspberry Pi"와는 다른 제품이니 액세서리/데드캣 구매 시 혼동 주의)
- 데드캣/윈드스크린은 지름 70mm보다 여유 있게(지름 8~9cm 원형 커버 기준) 준비

## 실험 목표 (4가지)

1. 속도별 풍절음 세기/특성 파악
2. 마이크 장착 위치(내부 vs 창문 외부)별 비교
3. 데드캣 유무에 따른 개선 효과 정량화
4. 풍절음/데드캣이 실제 **분류 정확도**와 **방향 추정(GCC-PHAT)**에 미치는 영향 확인

## ⚠️ 실험 전 사전 점검 (실험 당일 이전에 확인)

- **GCC-PHAT 자체 구현이 ReSpeaker v2.0 raw 채널(ch1~4)에서 실제로 동작하는지 먼저 테스트.** 현재 `현재_상태_요약.md` 기준으로 v2.0 raw 채널 기준 GCC-PHAT 검증 기록이 없음 — 안 되면 "방향 정확도" 항목은 이번 실험에서 제외
- 6채널 동시 녹음(`arecord -D hw:2,0 -r 16000 -c 6 -f S16_LE`) 스크립트에 조건별 파일명 자동 부여 기능 미리 준비 (현장에서 매번 명령어 치면 실수 발생)

## 조건 매트릭스 (독립변수)

| 변수 | 값 |
|---|---|
| 속도 | 정지(베이스라인) → 20km/h → 40km/h → 60km/h(안전 구간 확보 시) |
| 마이크 위치 | ① 차량 내부 대시보드 ② 창문 틈 거치 ③ 완전 외부(가능하면) |
| 데드캣 | 유 / 무 |

전체 조합 3×3×2=18개는 하루에 다 못 채우므로 **우선순위**:
1. 정지 베이스라인 (위치 3종 × 데드캣 유무) — 기준값 확보
2. 20km/h, 40km/h에서 위치 ①② × 데드캣 유무 — 가장 현실적인 시나리오
3. 시간 남으면 60km/h, 위치 ③ 추가

## 측정 절차

1. 각 조건당 최소 30초~1분 녹음, 같은 조건 2회 반복(재현성 확보)
2. 정지 상태에서 실제 경적/사이렌 소리를 스피커(휴대폰)로 재생하며 동시 녹음 → SNR 계산용 기준 신호 확보 (풍절음만 녹음하면 SNR 계산 불가)
3. 조건 전환 시마다 파일명에 메타데이터 인코딩: `speed40_pos-window_deadcat-on_01.wav` 형식 통일
4. 녹음과 별도로 노트 담당이 시각/조건/도로상황(직선·커브, 체감 풍향 등) 실시간 기록

## 측정 지표

- 원본 파형 RMS/피크 레벨 (풍절음 세기 정량화)
- 스펙트로그램 저주파(0~200Hz) 에너지 비중 (풍절음 특성)
- `03_Audio_Classification/code/realtime_classify.py`로 조건별 녹음 파일 통과시켜 confidence 변화 비교
- (GCC-PHAT 동작 확인되면) 조건별 방향 추정 오차

## 당일 고려사항 / 리스크

- **역할 분담**: 운전자(실험 조작 안 함) / 녹음·노트북 조작 / 타겟 음원 재생 / 조건·시각 기록 / 촬영(보고서용)
- **안전·법규**: 창문 밖 마이크 노출 실험은 한적한 도로·저속에서만, 낙하 방지 고정 확실히
- **전원**: Jetson+모니터용 차량 인버터/보조배터리 사전 확보
- **날씨 변수**: 자연풍 세기 기록해두고 보고서에 "이날 조건" 명시 (변수 통제 못한 부분도 스토리에 반영)
- **거치 고정**: 위치 변경 시마다 동일한 자리/각도로 고정 가능한 거치대(테이프/마운트) 준비 — 안 그러면 위치 변수 외 다른 변수가 섞임
