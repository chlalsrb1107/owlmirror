| | 오디오만 | 카메라만 | 카메라+LiDAR (채택) |

## 시스템 아키텍처 — Jetson/노트북 분리 (신규 확정)

기존에는 Jetson 한 대가 오디오+영상+거리+화면을 전부 처리하는 구조로 설계돼 있었으나, **Jetson은 오디오만 전담**하고 나머지는 노트북이 처리하는 구조로 전환됨.

```
[Jetson] 오디오 전담
  - 4채널 수음 (마이크 어레이 입력)
  - 소리 종류 분류 (사이렌·경적·배기음)
  - 소리 방향 추정 (오차 ±10~20°)
  → 초당 4회, 아래 JSON 한 줄만 노트북으로 전송 (영상·점군은 오가지 않음)

[노트북] 영상·거리·화면
  - 소리 방향에 해당하는 카메라 영상 확인
  - 경광등 점멸 검출 (평상시 경로, 학습 없이 ~0.5초)
  - 야간/악천후로 경광등이 안 보이면 소리 방향 변화 + 차량 움직임 대조 (대체 경로)
  - LiDAR로 후보 차량들의 거리 측정 → 소리 방향과 맞는 차량 특정
  - BEV 지도 + 테두리 알림으로 화면 표시
```

### Jetson→노트북 인터페이스 (JSON, 초당 4회)

```json
{
  "t": 1751250042.318,
  "class": "siren",
  "conf": 0.91,
  "theta": 194.0,
  "sigma": 12.0
}
```

| 필드 | 설명 |
|---|---|
| `t` | 분석 구간의 **중심 시각** (구간 시작 시각 아님) |
| `class` | `siren` / `horn` / `motorcycle` / `none` |
| `conf` | 0.0~1.0 |
| `theta` | 차량 좌표계 방위각 (전방 0°, 반시계 +) |
| `sigma` | 방향 오차 표준편차(도) — BEV 부채꼴 폭(`2×sigma`)에 사용 |

**시각 동기화 원칙**: LiDAR는 한 바퀴 스캔에 100ms가 걸려 같은 프레임 안에서도 관측 방향에 따라 최대 100ms 시각차가 생김(50km/h면 100ms에 약 1.4m 이동) → **프레임 시각이 아니라 점(대상)별 시각을 사용**해 오디오와 매칭. 자세한 내용은 `06_Display_Integration/ui_state_spec.md` §7 참고.

## 거리 추정 방식 전환 (중요 — 기존 설계 폐기)

- **기존**: RGB 단안거리 추정 (YOLO bbox 폭 기반) 또는 회의에서 논의됐던 "볼륨 변화 패턴 기반 거리 추정"
- **현재(확정)**: **"소리로 거리를 계산하려던 방식을 포기하고, LiDAR가 이미 측정한 차량 후보 중 소리 방향과 맞는 차량을 골라내는 방식"**으로 전환
  - 즉 거리는 LiDAR가 직접 측정하고, 오디오/카메라는 "어느 차량이 그 소리를 냈는지"를 지목하는 매칭 역할
- 볼륨 기반 거리 추정 아이디어(7/5 회의)는 최종적으로 **채택되지 않음**

## 화면(UI) 설계 (신규 — BEV 지도 중심으로 전환)

기존에 언급됐던 "카메라 영상 + HUD 오버레이"(`06_Display_Integration/영상_파이프라인.md`) 중심 설계에서, **위에서 내려다본 BEV(Bird's-Eye View) 지도를 주 화면으로** 쓰는 방식으로 전환. 카메라 영상은 위치 확정 시 또는 경적 감지 시에만 뜨는 보조 화면으로 격하됨.

- 상세 사양: `06_Display_Integration/ui_state_spec.md`
- 인터랙티브 목업: `06_Display_Integration/bev_mockup.html` (브라우저로 열어서 시나리오별 화면 확인 가능)

### 화면 상태 4단계

| 상태 | 의미 | 상단 알림 | 지도 | 테두리 빛 |
|---|---|---|---|---|
| `IDLE` | 소리 없음 | 없음 | 표시 안 함 | 없음 |
| `표시` | 주변에 있으나 위험 아님 | 회색 한 줄 | 회색 점 | 없음 |
| `주의` | 접근 중/위치 미확정 | 노란 막대 | 부채꼴 또는 노란 마커 | 약하게(45%) |
| `경고` | 근접/사각지대/차량 확정 | 빨간 막대 | 빨간 마커 또는 구역 점등 | 강하게(90%) |

- **원칙**: 지도는 감지된 모든 대상을 표시, 상단 알림·테두리 빛은 최우선 대상 하나만 반영
- **위치 미확정 시에는 특정 차량에 마커를 찍지 않고 부채꼴(방향+오차범위)로만 표시** — "잘못된 지목은 알려주지 않는 것보다 위험하다"는 원칙
- 상태 진입은 즉시, 하향/해제는 지연(3초 유지 후 0.5초에 걸쳐 해제) — 소리가 순간 끊겨도 알림이 깜빡이지 않도록

### 소리 우선순위 (동시 감지 시)

1. 오토바이·사각지대 진입 (충돌 최임박)
2. 오토바이·15m 이내 근접
3. 경적 (나를 향한 신호일 가능성)
4. 사이렌·차량 확정
5. 사이렌·위치 미확정
6. 오토바이·15~25m 접근
7. 오토바이·멀어짐 (알림 없음)

## 소리별 대응 방식 (오토바이 경고가 핵심 차별점)

| 소리 | 대응 |
|---|---|
| 사이렌(긴급차량) | 경광등 점멸로 찾음 → LiDAR로 거리 측정 → 지도에 차량 위치 표시 |
| 배기음(오토바이) | 골목·근접 주행 모두 대응, 벽 뒤는 소리로 미리 감지, 가까이 붙으면 지도 표시, 위험도 단계 구분 |
| 경적(일반 차량) | 즉각 방향 표시 + 해당 방향 카메라, **거리는 추정하지 않음** |

### 오토바이 경고 5단계

| 상황 | 단계 | 화면 표시 |
|---|---|---|
| 주변에 있으나 멀어짐 | 표시 | 회색 점, 알림 없음 |
| 15~25m 접근 | 주의 | 노란 마커 |
| 15m 이내 근접 | 경고 | 빨간 마커 + 테두리 빛 (깜빡임 주기 = 거리에 반비례, 0.3~1.2초) |
| 사각지대(반경 6m 이내, LiDAR 사각) 진입 | 경고 | 점 대신 **사각 구역 자체를 점등** (0.3초 고정 깜빡임) — 없는 정확도를 있는 것처럼 보이지 않기 위함 |
| 벽에 가린 골목 | 주의 | 부채꼴 + "시야 밖" 표시, 방향은 오토바이가 아니라 **골목 입구**를 가리킴 |

> 도심에서 매번 경고하면 운전자가 곧 알림을 무시하게 됨 → 상황별 단계 구분이 핵심. 기존 양산 차량 경고 기능(옆 차선 일부만 감지)과 달리 **360° 전방향 + 벽 뒤 골목 감지**가 차별점.

## 차별화 방향 (작년 임베디드SW 경진대회 대상작과 겹치면 안 됨 — 유지)

- 작년 대상작이 이미 커버한 영역: 룸미러 방향 텍스트/화살표, 시트·핸들 진동 피드백
- 확정 차별점:
  1. **오토바이 사각지대/골목 경고**: 카메라·LiDAR가 볼 수 없는 곳(벽 뒤, 반경 6m 이내 사각)을 소리로 먼저 감지 — 소리 센서를 쓰는 이유를 가장 잘 보여주는 기능으로 재확인됨
  2. **BEV 지도 + 상태 기반 알림 설계**: 단순 방향 알림이 아니라 위치 확정 여부·위험도에 따라 표현을 달리하는 판단형 UI
  - (기존에 언급됐던 "BLE 폰/워치 컴패니언 알림"은 이번 중간보고 자료에는 언급 없음 — 로드맵 여부 재확인 필요)

| 단계 | 내용 | 상태 |
|---|---|---|
| M1 | 소리 인식 개선 — 방풍 커버 장착 후 주행 정확도 재측정 | 준비 |
| M2 | 방향 추정 — 사이렌 전용 방향 추정 적용 | 준비 |
| M3 | 카메라 전환 — 소리 방향 카메라 화면 자동 표시 | **시연 가능** |
| M4 | 경광등 검출 — 점멸 인식 + LiDAR 거리 연결 | 확장 |
| M5 | 오토바이 경고 — 배기음 데이터 수집, 골목·근접 경고 | 확장 |

- **3단계(M3) 이후로는 언제든 시연 가능한 상태 유지**가 목표
- 측정 항목: 인식 정확도(속도별·소리 종류별), 방향 오차(실제 각도 대비), 지목 정확도(정답 차량 선택률), 오경보 횟수(일반 주행 10분당)
- 시험 방법: 다른 차량 지붕에 스피커를 얹고 함께 주행 → 그 차량이 정답. 긴급차량은 별도 학습 데이터 불필요, **오토바이 배기음만 직접 녹음** 필요 (주행 소음 섞어 학습해야 실도로 성능 유지)
