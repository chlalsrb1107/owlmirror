## 확정 하드웨어

- Jetson Orin Nano Super Developer Kit (8GB)
- ReSpeaker 4 Mic Array **v2.0** (UAC1.0, USB ID `2886:0018`, **실측 6채널** — ch0 AEC 처리 채널/ch1~4 raw/ch5 playback ref) — `01_Hardware/ReSpeaker_설정.md` 참고
  - ⚠️ 2026-07-05 정정: 기존에 v3.0(XVF-3800, 4ch, USB-C)으로 기록되어 있었으나 실측 결과 v2.0(6ch)이 확정 하드웨어임. DoA HID 코드는 v3.0 전용이라 재작성 필요
- **Depth 카메라: Orbbec Gemini 215 확정 구매/보유중**
  - RGB FOV: 74.7°×46.2° / Depth FOV: 63.5°×45.6°
  - ⚠️ **뎁스 유효 측정거리 0.15~0.70m뿐** — 근접 3D스캔용 카메라라 도로 위 차량(수 m~수십 m) 거리 측정이 물리적으로 불가능
  - → 거리는 Depth 스트림이 아니라 **RGB 스트림의 YOLO 바운딩박스 폭 기반 단안(monocular) 거리 추정**으로 대체
    - `거리(m) = (실제 폭 × focal_px) / bbox 폭_px`, `focal_px = (이미지가로해상도/2) / tan(수평FOV/2)`
    - 차량 평균폭 ≈1.8m, 오토바이 ≈0.8m 기준값 사용
  - Depth 스트림은 70cm 이내 초근접 경고 등 부가 기능으로만 활용
- 차량용 디스플레이: 미구매

## 실시간 추론 파이프라인 검증 완료 (2026-07-05)

Jetson + ReSpeaker로 실제 소리 입력 → 분류까지 엔드투엔드로 동작 확인함.

- 모델 체크포인트(`outputs_ast.zip` → `03_Audio_Classification/model_outputs/outputs_ast/best.pt`, 345MB라 저장소엔 미포함 — 폴더 내 README 참고)를 Jetson으로 이전, `transformers`의 `ASTForAudioClassification`으로 로드 성공 (missing/unexpected keys 없이 정확히 일치)
  - 베이스: `MIT/ast-finetuned-audioset-10-10-0.4593`, UrbanSound8K 10클래스로 파인튜닝, 파라미터 86.2M
  - 검증 정확도 91.0% (`summary.json` 기준, n=837)
- 실행 스크립트: `03_Audio_Classification/code/realtime_classify.py` — ReSpeaker 6ch 캡처 → ch0(AEC 처리 채널) 추출 → AST FeatureExtractor(16kHz, 128 mel bin) → 모델 추론 → top-k 확률 출력
- 라이브 테스트 결과: 실제 마이크 입력 3초 캡처 → 추론까지 정상 동작 (예: 주변 소음에 대해 `dog_bark 93.2%` 출력)
- **실제 음원 검증**: 유튜브 자동차 경적/구급차 사이렌 영상을 스피커로 재생해 ReSpeaker로 캡처 → `siren 95.7%`, `car_horn 94.2%/93.4%`로 정확히 분류. 이 두 클래스는 최종 타겟 4클래스(경적/사이렌/배기음/배경) 중 2개와 정확히 일치 — 파이프라인 검증을 넘어 실제 타겟 소리에 대한 조기 신호로 유의미함
- **CPU 추론 지연 시간: 3초 오디오 → 추론 약 3.9초** (Jetson 내장 GPU는 일반 pip torch로는 인식 안 되어 CPU로만 동작 중). 실시간(수백ms) 처리를 위해서는 TensorRT 변환/양자화가 추후 필요 — `03_Audio_Classification/모델_아키텍처.md`에서 언급된 TRT 변환 단계가 이 지연 해소의 핵심
- **알려진 한계**: 학습 클래스에 "무음/배경(background)" 클래스가 없어 어떤 소리든(엔진 소음, 정적 등) 10개 클래스 중 하나로 강제 분류됨 → 최종 4클래스(car_horn/emergency_siren/motorcycle_exhaust/background) 모델 재학습 시 background 클래스 포함 필수

## 위치추정 (방향, 거리 아님)

- ReSpeaker 하드웨어 DoA(`AEC_AZIMUTH_VALUES`, v3.0 host_control 명령) + GCC-PHAT 자체 구현을 교차검증
- 빔포밍(SRP-PHAT)은 방향 정밀화용
- **TDoA/빔포밍은 방향(각도)만 제공, 거리는 원천적으로 못 구함** — 마이크 어레이 반경(4.3cm)이 음원 거리에 비해 너무 작아 평면파 가정을 쓰기 때문. 거리는 카메라(RGB 단안거리)가 전담.

## 카메라 트래킹 설계

- 고정 카메라 + FOV 내 ROI 방식 채택 (PTZ 모터 방식은 9일 안에는 리스크가 커서 보류, 본평가 로드맵으로만 언급)
- DoA 각도가 카메라 FOV(약 ±32° = 63.5°/2) 밖이면 영상 없이 **방향 텍스트 알림만** 표시
- 동일 방향에 후보 차량이 여럿일 때 우선순위 스코어:
  `점수 = 클래스가중치(사이렌=3, 배기음=2, 경적=1) × (1/추정거리) × confidence`
  → 최고점 차량만 강조 표시, 나머지는 보조 표시

## 차별화 방향 (중요 — 작년 임베디드SW 경진대회 대상작과 겹치면 안 됨)

- 작년 대상작이 이미 커버한 영역: 룸미러 방향 텍스트/화살표 표시, 시트·핸들 진동 피드백
- 우리 차별점으로 확정한 방향:
  1. **예측형 위험도 판단**: DoA 각도 변화(칼만필터) + bbox 크기 변화(접근속도)로 "몇 초 후 경로 교차 예상" 등 지능형 판단 결과를 출력 (단순 방향 알림이 아니라 판단/추론 결과)
  2. **차량 개조 불필요한 폰/워치 컴패니언 알림**: Jetson이 판단한 결과를 BLE로 스마트폰/워치에 전송, 진동+표시. 특정 차량에 종속되지 않는 범용성이 장점
  - 카메라 영상은 판단 근거를 확인하는 보조 화면으로 유지 (기존 작업 그대로 재사용)
