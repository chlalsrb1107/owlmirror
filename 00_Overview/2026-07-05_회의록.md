## 1. 디스플레이

- **테두리 LED 라이트**: 요즘 출시되는 차량 방식(엠비언트 라이트)을 참고해 디스플레이 테두리에 LED 구현
- **서드파티 확장 컨셉**: 카플레이처럼 휴대폰을 연결하면 정보가 뜨는 방식을 참고, 우리 서비스를 부가 기능으로 얹어 이용하는 써드파티 접근 방식 채택
  - Q. 디스플레이에 실용적인 다른 기능을 추가할 수 있는가?
  - A. 자체 완결형 디스플레이가 아니라, 폰 연결 시 우리 서비스 정보가 함께 표시되는 확장형 구조로 설계

## 2. 실험 방법론 / 평가 전략

- 소리는 공용 효과(반사/공명)가 있으므로, 실험 시 벽 등에서 **최소 1m 이상 거리**를 두고 측정해야 함
  - 예: 화장실 같은 반향 공간에서 스피커를 바닥에 두고 대각선 끝에서 측정, 값 변화 확인
- **여러 환경에서 실험하고, 시도/노력 과정 자체를 보여줘야 함** — 중간평가 결과가 최종 평가에도 반영되기 때문
- 마무리 강조사항: **실험 과정에서 잘못 생각했던 점과 이를 극복하려 한 시도를 스토리로 구성**해서 보고서에 반영할 것

## 3. Q&A

**Q. Jetson이 계속 모델을 돌리다가 목표 음성 신호를 받으면?**
A. 실제 상용화 시에는 파인튜닝한 모델을 칩에 내장하는 방향까지 설명해야 함 → 단가 절감 + 지연시간(딜레이) 문제 극복 방안까지 제시 가능

**Q. 시속 20km만 되어도 바람 소리가 매우 큰데, 마이크는 어디에 설치할 것인가?**
A. 현재 마이크 어레이(ReSpeaker)는 실내용으로 설계됨. xVF-3800이 사람 음성을 추출하고 나머지를 노이즈로 처리하는 알고리즘 기반이라, 우리가 원하는 음원(경적/사이렌/배기음)까지 전부 노이즈로 취급돼 버리는 문제가 있음 → 풍절음 대응이 중간보고서까지 해결해야 할 과제

## 4. 마이크 하드웨어 방향 (핵심 검토사항)

### 4-1. 어레이 마이크(현재 ReSpeaker)를 계속 쓸 경우
- 오디오 프로세서 개발 라이브러리(자체 알고리즘 처리용 라이브러리) 제공 여부를 확인 필요
- **반드시 실차에 장착한 상태로 풍절음 실험**을 진행해야 함
  - **데드캣(윈드스크린, 마이크에 씌우는 솜뭉치)** 사용 → 바람이 솜 사이에 걸려 풍절음 저감 효과
  - 자동차 주행 중 창문 밖으로 마이크를 내민 상태로 측정해볼 것

### 4-2. 어레이 마이크를 안 쓸 경우 (대안)
- **지향성 마이크 4개**를 구매해 4곳에 부착, low-level 데이터를 직접 받아 로직을 자체 구현하는 방향
- 학습 결과로 나온 보정값이 이 마이크 입력에 반영되도록 구성
- 입력값을 필터링해 어떤 음원인지 식별하는 구조

### 4-3. 실행 항목
- **Seeed Studio ReSpeaker 4-Mic Array for Raspberry Pi 2개 구매**, 여기에 외부 마이크를 연결해 테스트 진행
- Seeed Studio의 다른 제품 라인업도 추가로 조사

## 5. 데이터 수집

- **오토바이 배기음**: 전용 공개 데이터셋이 없으므로
  1. 실제 오토바이 소리를 직접 녹음(노이즈 제거 포함)하거나
  2. 일본 공개 데이터셋을 참고

## 6. 거리 추정 아이디어 (볼륨 기반)

- 접근하는 물체의 소리가 **처음 들린 시점의 크기값**과, 이후 가까워지며 변하는 **소리 크기값의 차이**를 기준으로 거리를 추정하는 방식 제안
  - 주행 속도에 따라 소리가 처음 들리는 시점과 이후 커지는/작아지는 패턴이 달라짐 → 이 볼륨 변화 패턴을 학습시켜 거리 차이를 추정
  - 모든 케이스를 다 측정할 수는 없으므로, **제약조건을 걸어 인식 범위를 한정**하는 것이 목표임을 설명해야 함
- **데이터셋화 필요**: "볼륨 N일 때 실제 거리 M" 형태로 실외에서 직접 측정해 학습 데이터 구축

> ⚠️ 참고: [[현재_상태_요약]]에는 현재 "TDoA/빔포밍은 방향만 제공, 거리는 카메라(RGB 단안거리 추정)가 전담"으로 정리되어 있음. 이번 회의에서 나온 볼륨 기반 거리 추정은 카메라 방식과 별개의 오디오 기반 보조/대안 접근으로, 실제 채택 여부는 추가 논의 필요.
